## 它的动画模型：命令式 async 编排，不是时间线

```js
function createShow(stage, options) {
  function sleep(ms) { /* 可取消：跳过时整条链一起 reject */ }
  function later(fn, ms) { /* 可取消的 setTimeout */ }
  async function playBoot() {
    for (const item of sorted) { await sleep(300); item.el.classList.add('draw'); }
  }
}
```

- **`sleep` / `later` 都可取消**：用户跳过时，`cancelled` 一置位，整条 Promise 链一起 reject，
  不会出现"跳过之后还有定时器在后台改 DOM"这种鬼故事。这是它做得最稳的一点。
- **两级模式**：`simple`（只演 logo）/ `full`（logo → HUD → 覆盖阶段）。
  简单模式完全不碰 `#app` 的 DOM，避免没挂载的节点报错。
- **分阶段 `await`**，每段自己算时长；没有统一时间轴，改顺序要改代码。

### 和我们的区别

| | 550C | 我们 |
| --- | --- | --- |
| 编排方式 | 命令式 async 链 | 声明式时间线（关键帧 + 时间窗） |
| 编辑 | 改代码 | 编辑器里拖 |
| 跳过/取消 | 全局 cancelled 标志 | `__DSH_STARTUP_API__.skip()` |
| 复用 | 一个模板 | 模板 + 图层/效果积木 |

**可以借的**：全局取消标志要覆盖所有定时器（我们已经有 skip，但部分 setTimeout 没接取消）；
两级模式（simple / full）值得学——我们可以在模板里加 `minimal` 变体，低配机器只演主视觉。

## 追加：「地球化成 WELCOME BACK」是怎么做的（preview/ueg.html 972–1120 行）

不是把地球换成文字贴图，而是**同一批字符粒子从球面飞成字形**。分四步：

### 1. 先离线量字，得到落点

```js
board.width = innerWidth; board.height = innerHeight
bctx2.font = `800 ${size}px "Segoe UI"`
bctx2.fillText('WELCOME BACK', W/2, H/2)
// 读 alpha，5px 网格 + ±1px 抖动采样
// 八邻域里只要有一个在字外 → 判定为"轮廓点"
```

- **自适应字号**：量出文字实际宽度，超过屏宽 86% 就按比例缩小字号，避免两头被切
- **轮廓/内部分类**：后面用"亮粒子走轮廓、暗粒子填内部"，字形才立得住
- **均匀抽稀**：`stride = round(hits.length/1500)` 后 `filter(index % stride)`，
  而不是 `slice(0, 1500)` —— 后者会让字的下半/右半缺一块

### 2. 起点直接复用地球上的字符点

```js
// 地球是用字符画的（cellInk 记录每个格子的"墨量"）
// 按墨量均值把 256 个格子分成 bright / dim 两池
// 亮粒子飞向轮廓点，暗粒子飞向内部点
```

**关键点**：淡出与淡入是同一批粒子，没有换主体，所以看着是"球散开变成字"，
而不是"球消失 + 字出现"。

### 3. 冻结起点、逐帧插值

```js
finaleOrigin = 终幕开始时地球的屏幕位置（冻结，不再跟随）
每帧：p = lerp(origin + 粒子在球上的偏移, 目标点, ease(t))
```

- 起点必须**冻结**，否则地球还在动，粒子会"拖尾"
- 缓动全程一条，不做分段，避免中途速度突变

### 4. 交接：先显示真地球，下一帧再撤代码层

```js
document.getElementById('globeLayer').style.opacity = '1'
requestAnimationFrame(() => burst.classList.remove('on'))   // 下一帧才撤
```

注释写得很实在：**顺序反了（或同帧一隐一显）就会有一帧空白，看着就是交接处"一顿"**。

## 我们能不能做

能，而且比它省事——我们已经有：

| 需要的东西 | 我们有吗 |
| --- | --- |
| 字符/方块粒子（位置逐帧可算） | 有（线描鲸鱼、旧方块层） |
| 离线量字取落点 | **要新写**：canvas 画字 → 读 alpha → 采点（约 40 行） |
| 粒子从 A 飞到 B 的插值 | 有（关键帧 + 缓动） |
| 球面字符粒子 | 地球仪是 SVG 海岸线，不是字符粒子 → 需要单独一个"字符地球" |

**结论**：这个效果我们目前做不了"原版"，因为我们没有"字符画地球"那个主体。
但可以做**变体**：线描鲸鱼/地球 → 粒子化 → 飞成任意文字。
工作量约一次会话（量字取点 + 粒子池 + 插值 + 交接时序）。
## 字符粒子的三件套（2026-10-19 补充）

| 组成 | 550C 做法 | 我们现在的做法 |
| --- | --- | --- |
| 陆地点云 | 从徽记地球烘成经纬字节（2 字节/点），atob 解码 | 用海岸线环做点在多边形采样 → 2650 点 JSON |
| 字形 | 256 格十六进制图集（0A~FF），离屏 canvas 一次画好 | 同（运行时生成，按颜色缓存） |
| 绘制 | 绕极轴转 θ、正交投影、facing 控亮度，每 6 点一个字 | 同（chars 图层） |

**关键理解**：所谓"字符粒子"= 点云 + 字形图集 + 逐帧投影。
既不是视频，也不是贴图序列；所以任意分辨率、任意颜色、任意转速都行。
