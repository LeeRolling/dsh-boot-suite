# 编码方式 · 几何数据与正射投影

> 来源：外援提供的 `F:\Lee的GitHub仓库\可旋转地球线稿`（`globe.js` + `continents-detailed.json`）。
> 这份文档记录我们**学到并采纳**的写法，避免以后又写回"每帧重建 DOM"那种笨办法。

## 1. 数据用地理坐标，不用屏幕坐标

```json
{ "type": "FeatureCollection",
  "features": [{ "properties": { "name": "Africa", "name_zh": "非洲" },
    "geometry": { "type": "MultiPolygon",
      "coordinates": [[[[-17.5, 14.7], [0.0, 0.0], ...]]] } }] }
```

- 坐标是 **[经度, 纬度]（度）**，保留 3 位小数即可（±0.001° ≈ 111m，片头够用）
- 用 GeoJSON 的 MultiPolygon 而不是自创格式：任何 GIS 工具都能产出/校验
- **好处**：同一个数据集既能做正射投影（球），也能做等距圆柱投影（平面地图），
  换投影不用换数据；旋转只是改一个角度变量

## 2. 投影是每帧的纯函数

```js
function project(lonDeg, latDeg) {
  const lon = lonDeg*Math.PI/180, lat = latDeg*Math.PI/180
  const d = lon - rotation, cl = Math.cos(lat), sl = Math.sin(lat), cd = Math.cos(d)
  return { x: R*cl*Math.sin(d),
           y: -R*(sl*Math.cos(tilt) - cl*cd*Math.sin(tilt)),
           z: sl*Math.sin(tilt) + cl*cd*Math.cos(tilt) }  // z<0 = 背面
}
```

- `rotation` / `tilt` 是两个标量，交互（拖动）和自动旋转都只改它们
- **z 判断可见性**，不可见的点直接跳过 → 天然不会画到背面
- 跨越地平线的一段，用**二分法**找 z=0 的交点，路径在那里断开
  （不做这一步就会出现"穿过地球的直线"，这是最容易翻车的地方）

## 3. DOM 只建一次，每帧只改属性

```js
coastPaths = rings.map(() => svgPath('coast', landLayer))  // 建一次
// 每帧：
rings.forEach((ring, i) => coastPaths[i].setAttribute('d', ringPath(ring)))
```

**这条最值钱。** 我们原来的地球实现是每帧 `removeChild` 全删再重建，
55 条路径 × 60fps = 每秒 3300 次 DOM 插入/删除。改成复用后节点数稳定在 76 个。

## 4. 数据两路加载

```js
if (window.CONTINENTS_DETAILED) initialize(...)          // 双击 index.html 也能跑
else fetch('continents-detailed.json').then(initialize)  // 正规加载
```

- 本地 `file://` 下 fetch 会被安全策略拦，所以同时提供 `continents-detailed.js`（挂全局）
- 我们的插件是从宿主 HTTP 路由加载的，**优先走 fetch**；全局变量只作兜底

## 5. 什么都不依赖

- 无 canvas、无 WebGL、无第三方库：`<svg>` + `<path>` + 纯函数
- 网格代码生成（每 30° 一条），不占数据体积
- 地球本体 = 1 个 `<circle>`（裁剪）+ N 条海岸线 + 轮廓圈

## 给以后写新形状的人

1. **能用坐标数据就别写死路径**：等高线、海岸线、星空、星座都能用点集描述。
2. **每帧只更新 `d`/`transform`**，不要增删节点。
3. **先在 2D 里验证形状**，再加投影；投影出错时先关掉 z 裁切看原始点。
4. **点数要抽稀**：1080 个点足够画地球，40k 个点会拖死 30fps。
