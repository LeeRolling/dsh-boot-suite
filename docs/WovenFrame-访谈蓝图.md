## 待访谈验证的矛盾（collisions）

- **C1 复杂度**：10 分钟时间线 / 多轨 / 片段拼接 / 转场（编辑器思维） vs "用户需求不复杂、模板+参数就够"（模板思维）——v3 里这些到底留多少？
- **C2 用户能力**：许愿式要求用户说得出想要什么 vs 用户自己观察到"99% 是伸手党"——愿望从哪来（模板名？示例？一句话？）
- **C3 功能承诺**：MCP / Agent / 参考视频复刻曾定为 P0 vs "模板比编辑器简单"的最小路径——MCP 要不要延后？
- **C4 可持续性**：MIT 免费 + 不做店内评分 + 收入未定 vs 长期投入——是否接受"纯爱好/用爱发电"定位？
- **C5 商店 vs 用户**：一模板一仓 / GitHub star 面向会 GitHub 的人，而伸手党不登录——谁发模板、谁消费、怎么触达？
- **C6 模板形态**：播放器只吃 template.json、编辑器导出同一份 JSON，但用户导入视频/图片也会生成"模板"——模板到底有几种形态（纯视频 / 代码动画 / 混合）？
- **C7 341 模板 vs 自研模板**：用 341 风格批量生成模板（快、但风格上限） vs 手工做少量精品（慢、但差异化）——首发怎么配比？

## 记录

### Q1 — 首发主用户：做模板的人（创作者） vs 用模板的人（消费者）

**矛盾**：过去拍板（一模板一仓、GitHub star、参考视频复刻、MCP/Agent、10 分钟多轨时间线、参数自定义）全是为"做模板的人"设计的创作者工具；而"许愿为主"服务的是"用模板的人"（伸手党、不登录 GitHub、不懂代码、一键装）。两个项目的竞品、成功指标、复杂度完全不同，资源只够一个。

**回答（用户原话，2026-10-30）**：「我选，用模板的人。理由：先有好看的模板，再谈怎么制作。很多优质的视频也好，游戏也罢。均为，先优质，再谈如何制作。不然一切都是空谈。借用网络上的一句话：'我成功了，我赚到钱了，我说什么都是对的。'至于我怎么成功的，我们后面再谈。我发现很大部分都是这样，就比如 DeepSeek 梁文锋，一开始都没人知道他。一直到 DeepSeek 横空出世。」

*Consequence：* ①创作者侧设施全部降级/推迟：一模板一仓、GitHub star、registry、参数面板、多轨时间线、MCP/Agent、参考视频复刻、独立 webUI 编辑器——伸手党不会为装模板打开独立网页、登录 GitHub、理解仓库结构。②成功指标改为消费者侧：安装量、使用/留存、传播。③竞品改为 Wallpaper Engine、剪映同款、手机主题商店。④"WovenFrame 平台"在 v1 可能不应存在，应缩成 dsh-boot-suite 的模板商城页 + 精品模板包。

**新增矛盾（与既有决定冲突）**：

- **C8 消费者 vs 创作者向设施**：上一段列出的设施全部为创作者设计，用户却选了消费者 → 这些设施的首发地位必须整体重排。
- **C9 "先有好看的模板" vs 现有资产**：341 条是"风格提示词/配方"（教怎么制作），不是消费者可直接装的成品模板；目前成品模板 ≈ 0（dsh-boot-suite 自带几个 demo）。

### Q2 — 消费者路线下，v1 还叫"WovenFrame 平台/编辑器"吗？

**问题**：v1 是缩成"插件里的模板商城 + 一包精品模板"（= dsh-boot-suite 下一版），还是坚持先建独立 Web 平台/编辑器？
**选项**：A 缩成插件（编辑器/MCP/独立 webUI/registry 全部推迟 v2+）；B 坚持平台（必须回答：伸手党凭什么会打开它）。
**回答（用户原话，2026-10-30）**：「缩减成为 A。商店模板成为插件的一部分。但是我们注册好的东西现在不用，但是以后可能会用也可能不会用。反正我们都已经占位了。我的想法是，现在我们先自己做一部分'至少自认为优秀的模板'免费放出去。让大家用。大家用多了，自然就会开始有人专研怎么制作模板了。然后就会从：开始许愿➡️小修小改➡️完全独立制作。这个过程。」

*Consequence：*

- **v1 形态定稿**：dsh-boot-suite 下一版——插件内模板商城页（浏览/预览/一键装/换/最近使用）+ 20–30 个精品模板；不再有独立 Web 平台。
- WovenFrame 组织/registry/star/评分/参数面板/多轨/MCP/参考复刻/独立编辑器 → 全部 **v2+ 候选，不入 v1**；已注册占位保留（可能用、可能不用）。
- 模板内容责任：先由我们自己生产"至少自认为优秀"的一批，免费放出。
- 用户首次给出长期成长路径：**许愿 → 小修小改 → 完全独立制作**（产品阶梯，非 v1 功能）。
- 成败判据前移：v1 几乎全押在"模板好不好看 + 装得顺不顺"。

**新增矛盾**：

- **C10 成长路径 vs v1 无编辑器**：许愿/小修小改/独立制作都需要编辑器，而 Q2 选了 A（编辑器推迟）→ 成长路径在 v1 无法启动。要么 v1 留"微调"（参数面板），要么接受 v1 纯消费、路径从 v2 开始。
- **C11 "自认为优秀" 无外部标准**：谁定义好看、按什么验收、要不要反馈闭环——未定。

### Q3 — v1 装完模板后，用户能不能"改一点"？（决定 v1 是否带参数面板）

**问题**：v1 模板是"只能看/装/换的成品包"，还是"可微调（3–6 个参数）"？
**选项**：A 纯消费（不可改）；B 带微调（标题/副标题/配色/时长/素材图，插件设置页内改，不打开编辑器）；C 其他。
**回答（用户原话，2026-10-30）**：「B，用户可微调。跟现在的模板一样，主动暴露部分可修改的参数。可修改参数为，每个模板自定义。不需要统一。」

*事实核对（不写未验证前提）*：**现在的模板没有"参数"这一层**。`template.json` 是固定 schema（schemaVersion 1/2：theme / layers / keyframes / segments），装上即播；插件 UI 没有给终端用户改参数的入口（代码里的"参数"只是编辑器内部音效预设、归一化白名单）。所以"跟现在的模板一样"不成立——**微调是新增工程**：模板加 `params` 声明 + 设置页按声明动态渲染 + 改完即时预览。

*Consequence：*

- v1 新增一块工程：模板参数 schema（每模板自定义）+ 设置页动态表单 + 预览。估计占 v1 开发量的大头之一。
- 模板生产方式升级：每做一个模板，要同时设计"暴露哪些参数"——这是作者的设计决策，不是自动可得的。
- "小修小改"在 v1 有限度成立，成长路径第一级落地。

**新增矛盾 C12 — 渠道 vs 受众**：v1 渠道 = DSH 插件内商城 → 只能触达"用 DSH 且装插件"的人；而 Q1 主用户 = "用模板的人"（伸手党）。两者交集有限；"根本不用 DSH 的普通人"完全触达不到。

### Q4 — v1 主打的"用模板的人"到底是哪一圈？

**选项**：A 已用 DSH、会装插件的人（渠道直达，多懂技术）；B 用 DSH 但从不装插件的人（需引导）；C 根本不用 DSH 的普通人（插件形态够不到，需另设触达方案）。
**回答（用户原话，2026-10-30）**：「我觉得这一题是：A+B，有一个事实理由：因为我们 B 站的视频下面，经常会有人在用 DSH，但是不会装插件。这个人数实际上不在少数。报错之后不会处理的也有。哪怕是 DeepSeek 这种强大的人工智能摆在他们的面前，他们也不会自己处理，然后把处理截图给我。目前能接触到的，最后截图过来的就只有 1 人。当然，这个结论有幸存者偏差嫌疑。」

**附带回答（模板参数类型）**：「每个模板现阶段要设计的主动暴露参数：我能想到的（因为我不是程序员，理论知识为 0）：就是修改部分文字。修改元素出现的时机。修改语音。至于让这个元素变成另外一个元素这种，我也不知道在模板上怎么体现。」

*Consequence：*

- 主用户 = A（会用插件的 DSH 用户）+ B（用 DSH 但不装插件的人）；C 暂不做。
- **B 圈的第一障碍是安装/排错，不是模板审美**——用户自述很多人不会装、报错不会处理、最终截图求助仅 1 人（自认幸存者偏差）。
- 参数类型收敛为三类可落地：**文本 / 时机（keyframes 的 t）/ 语音（音频资产）**；"元素变形"参数表达不了，留给编辑器/AI 阶段，不入 v1。
- 技术映射成立：文字→text 层；时机→keyframes 时间；语音→音频资产；无需新引擎。

**新增冲突 C13 — 顺序**：用户命题"先有好看模板"，但 B 圈证据显示"装不上"是先于审美的漏斗。v1 优先补哪一环，需本人拍。

### Q5 — v1 的"一等公民"是模板内容，还是安装体验？

**选项**：A 双轮（商城 + 一键安装器：自动检测 DSH 目录/自动安装/装完自检/常见报错一键修复/升级卸载，安装体验算核心指标）；B 商城为主（安装沿用现有 cmd/手动，省工程，但 B 圈继续卡）；C 先安装器后商城（先做"我奶奶都会装"，模板先用现有 demo 顶着，商城排 v1.1）。
**回答（用户原话，2026-10-30）**：「这轮我选 A。用户在商城中看到心仪的模板之后，点击下载，自动安装。直接使用。多来几次他自己有想法要开始自己做了。这个需要交给时间。」（并追问"漏斗先堵哪一环"具体指什么）

*澄清（已向用户解释）*：漏斗 = 用户从"刷到视频"到"用上模板"的整条路径，每一站都会流失：①刷到视频 ②装 DSH ③装插件 ④打开商城 ⑤挑模板下载 ⑥改参数 ⑦生效。"堵哪一环"= 优先修流失最大的那一站。用户自己的证据指向 ②③⑦（装不上/报错不会处理/不生效），而不是 ⑤⑥（模板是否好看）——多数人没走到挑模板那一步。

*Consequence：*
- **v1 = 双轮**：模板商城 + 一键安装器（自动定位 DSH、自动安装、装完自检、常见报错一键修复、升级/卸载）。
- v1 范围正式变为四块工程并行：①安装器/诊断 ②商城 UI ③20–30 个精品模板 ④每模板参数层。比"只做商城"重得多，工期要按此重估。
- 用户对增长路径的判断：先让"下载→自动安装→直接用"顺滑，用多了自然有人想自己做——交给时间。
- **新增矛盾 C14 — 范围 vs 工期**：四块工程 + "至少自认为优秀"的质量要求，在无时间盒/无质量判据时不可估。

### Q6 — "优秀"由谁、按什么标准判定？

**选项**：A 你一个人拍板（每个模板你点头才过，最省沟通但你是瓶颈）；B 客观清单（按 341 风格库配方：构图/运动/配色/文字/时长，AI 自检+你抽查）；C 数据说话（先上 5–10 个，看下载/留存/评论再加量）。
**回答（用户原话，2026-10-30）**：「V1 的工程，不是选择题，是先后题。先让用户觉得模板好看、帅气。再谈安装。就像人类看上一个男生/女生，在完全不认识的情况下，肯定是自然先从外貌着手。这个是人类的自然属性，改不掉。」
「这一轮我选 D，先立几个标杆，而且标杆是我们重新制作。因为我已经有想法了。就算是模仿也好，复刻也罢。第一要素依旧是先吸引人过来看。让用户觉得'我想用这个模板'，然后再加上我们的一键安装，用户体验就得到了基本的满足。至于后面的修改，那就看用户自己是什么想法了。就比如我这种用户就喜欢自己琢磨和 DIY，有的用户装上了什么都不想改。」

*Consequence：*
- Q5 从"双轮"校正为**先后题**：内容（好看）先行，一键安装作为第二推力；不是并列。
- Q6 = **D 标杆法**，且标杆**重新制作**（可模仿/复刻），不直接复用 341 或现有 demo。
- 用户确认自己已有想法 → 下一步必须先把"想法"变成可执行的模板规格。
- 参数层的定位下调：v1 参数只服务"想改的人"（DIY 型），不爱改的人零操作即用——所以参数层可以后置到安装器之后。

**新增冲突 C15 — 顺序之争**：用户先判"装不上是最大流失"，随后改判"好看是先于安装的吸引力"。两者并不矛盾但优先级相反：v1 先做内容（吸引力）还是先做安装（转化率）？当前定：内容先行。
