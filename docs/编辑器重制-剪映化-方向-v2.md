## 1. Agent 层（P0）

### 1.1 为什么第一版就要

用户自述（2026-10-29）：100 个用户里可能只有 1 个能精准对 AI 表达意图，但 AI 进化极快——**接口先做进去，等模型变强时产品就绪**。所以 MCP 和 Agent 面板不是加分项，是地基。

### 1.2 三种协作模式

| 模式 | 行为 | 用户视角 |
|---|---|---|
| **问答** | Agent 只回答/解释，不碰工程 | 右侧聊天窗，可附当前选中元素、时间码 |
| **建议** | Agent 给方案 + 「应用」按钮，用户点才改 | 每步可预览、可拒绝 |
| **执行** | Agent 直接操作，边做边高亮，可随时暂停/接管/撤销 | 像看思维链一样看它操作 |

「执行」不是黑盒：Agent 的每次工具调用 = 一条**可回放的操作事件**（命令模式，可逆、可 undo）。

### 1.3 Agent 对话面板（UI）

- 位置：右侧面板可切换「检查器 / Agent」，或底部抽屉（默认右侧，宽 320–380px）
- 内容：对话流 + **操作卡片**（如「已添加图层：圆」「已设置旋转 2s」「已变形为五角星」）+ 截图/帧缩略图
- 上下文条：当前项目摘要、选中对象、播放头时间码、上一步操作
- 输入：文字 + 可选附件（参考帧、素材）
- 控制：提交 / 停止 / 全部撤销 / 逐步确认开关（危险操作强制确认）
- 展示的是**计划与操作步骤**，不是模型原始推理（多数 API 不返回 raw CoT；我们把「计划→工具调用→结果」做成可读流）

### 1.4 操作可视化协议（关键设计）

```
Agent 计划  ──►  工具调用（MCP）  ──►  命令总线  ──►  编辑器执行
                                        │
                                        └─► UI 高亮/动画：目标元素闪烁 + 参数气泡 + 「撤销」按钮
```

- 每条命令：`{id, actor: 'agent'|'user', tool, args, undoable, viewHint}`
- UI 按 viewHint 做「指给你看」：高亮图层、飞到时间码、打开对应检查器 tab
- 用户可：暂停（在下一个命令前停）、接管（Auto→Copilot）、撤销单步/整段
- 所有命令进操作日志，支持回放（复现/教学/测试）

### 1.5 参考视频复刻工作流（P0 场景）

用户：把参考视频拖上时间线，Agent 一帧一帧或跳帧读，直接在 UI 上操作复刻，用户看着过程并指定修改点。

```
1. 导入参考视频 → 「参考轨」（reference track，半透明叠加/分屏对照）
2. Agent 抽帧：场景检测（镜头切点）+ 采样（默认 2fps + 每个切点前后各 2 帧）
3. 逐帧视觉理解（多模态模型）→ 生成「分镜表」：每段的时间范围/元素/文字/颜色/主要动作
4. 生成 IR 草稿（分镜级）+ 与参考逐段对照（左参考右复刻/叠加透明）
5. 用户圈出「要改的几项」（如换 logo、换主色、换文案）
6. Agent 定点修改 IR → 逐段预览 → 通过
7. 导出（模板 JSON / 视频）
```

技术要点：
- host 提供 **frame server**：`get_frame(t)` / `get_frames([t...])` 返回 PNG（解码用 ffmpeg 或 WebCodecs），MCP 工具可直接调用
- 视觉 provider：走多模态模型（GLM-4V / Qwen-VL / Kimi vision 等；DSH 侧按能力选择）
- 复刻结果必须**可编辑**：先生成 IR，再逐段调，不直接把参考视频当素材用
- 版权提示：参考视频仅用于用户本地复刻自己的作品/授权作品；商店模板禁止承载他人版权内容（规则待定）

### 1.6 权限与安全（Agent）

- 分级：只读（读工程/帧）→ 编辑（增删改图层/动作）→ 渲染（预览）→ 导出（写文件）→ 商店（上传）
- 危险操作（导出、删除项目、上传商店）必须用户点确认
- Agent 上下文里只放「项目摘要 + 用户明确提供的素材」，不自动上传整个磁盘
- 审计日志：每个 agent 会话说清用了哪个 provider/model、花了多少、改了哪些命令

## 2. MCP 第一版（P0）

### 2.1 定位

**编辑器的标准遥控器**：任何支持 MCP 的客户端（DSH、Codex、Claude Code、其他 host）都能操作编辑器；DSH 自身走同一条命令总线（不必绕 MCP 网络）。

- Transport：stdio（本地 CLI 客户端）+ HTTP/SSE（桌面/DSH 进程），仅 localhost
- 认证：一次性 token（插件签发），CORS/Origin 白名单；不监听 0.0.0.0
- 一次只允许一个「执行者」持有编辑锁（避免人机同时改）

### 2.2 Tools v1（建议清单）

| 工具 | 作用 | 权限 |
|---|---|---|
| `get_project` | 项目摘要/schema/时长/轨道 | 只读 |
| `get_timeline` | 完整 IR/时间轴结构 | 只读 |
| `get_selection` | 当前选中对象/播放头 | 只读 |
| `get_frame` / `get_frames` | 单帧/多帧 PNG（参考复刻用） | 只读 |
| `import_reference` | 导入参考视频到参考轨 | 编辑 |
| `add_layer` / `update_layer` / `delete_layer` | 图层增删改 | 编辑 |
| `add_cue` / `update_cue` / `delete_cue` | 动作卡增删改 | 编辑 |
| `apply_ir` | 应用一段完整 IR（diff 视图） | 编辑 |
| `preview` / `render_preview` | 播放/渲染预览片段 | 渲染 |
| `export` | 导出视频/模板包 | 导出（需确认） |
| `undo` / `redo` | 撤销重做 | 编辑 |
| `search_templates` / `get_template` | 本地模板库/商店检索 | 只读（商店） |
| `upload_template` | 上传到商店 | 商店（需确认） |
| `get_operation_log` | 读操作日志（教学/复盘） | 只读 |

### 2.3 与其他 AI 的关系

- 默认 provider = 本机 DSH（自动发现，无需 key）
- 也可让 DSH/Codex 通过 MCP 当 Agent 操作编辑器
- Agent 面板里的模型调用与 MCP 执行共用同一个命令总线，保证「用户点」和「Agent 做」行为一致、都可撤销

## 3. DSH 联动（P1）

### 3.1 拉起与握手

- 插件里一个按钮：启动本机 localhost 编辑器服务（Node/宿主进程）→ 浏览器打开 `http://127.0.0.1:<port>/?token=...`
- token 一次性、短时效；服务只绑 127.0.0.1；关闭即失效
- 编辑器检测「是否由 DSH 拉起」，是则显示「已连接 DSH」标识

### 3.2 单独上下文窗口（解释与辅助）

- 用户可开一个 DSH 会话窗口（独立上下文），专门用来问「这个编辑器怎么用/刚才那步是什么意思/帮我解释这个模板」
- 编辑器需把**项目摘要**打包给 DSH：`{项目名, 时长, 轨道结构, 选中对象, 最近 N 步操作, 当前报错, 模板 schemaVersion}`
- DSH 侧回答可一键「回填」到编辑器 Agent 面板（或直接给出操作建议）

### 3.3 待验证（M0 技术项）

- DSH 插件是否支持：创建新会话/向会话注入消息/侧栏面板/读取用户操作日志
- 若不支持：先走「打开 DSH 会话页 + URL 参数带上下文」的降级方案
- 编辑器与 DSH 谁持有 Agent 会话：建议编辑器持有对话，DSH 作为 provider（避免双份上下文互相打架）

## 4. 时间轴规格（v2.1：产品 10 分钟 / 引擎 11 分钟余量）

- **产品上限 600s（10 分钟）/项目**（UI 展示）；**引擎能力上限 660s（11 分钟）**（内部常量与格式能力，不对外展示）
- 默认项目 30s；UI 缩放档位：10s / 30s / 1min / 3min / 10min / 适应窗口
- 帧率：默认 30fps（长视频）；短片/启动动画可选 60fps；引擎支持 24/30/60
- 10min@30fps = 18,000 帧；10min@60fps = 36,000 帧；660s@60 = 39,600 帧
- 预览：长项目自动降级（缩略渲染/低帧率/分块缓存），最终渲染全质量；导出为后台任务、分段编码
- 性能预算：1080p、30 图层、10 分钟项目；超时自动降预览质量
- 引擎余量用途：打开/导入第三方超 600s 项目、未来放宽上限时不破格式

- 模板包体积目标：≤ 20MB（不含视频素材）；商店预览图/预览视频单独存

## 5. 场景聚焦：启动动画 + 「CSV 这类动画演示」

### 5.1 启动动画专用能力

- 导出双形态：**模板 JSON（给启动播放器直接吃）** + **MP4/WebM（通用）**；两者必须一致（同一 renderer）
- 首帧注入、循环点（loop 标记）、音画同步、结束交接（这些是插件启动动画的既有契约，编辑器必须保留）
- 预设主题：终端 / 档案 / 深海 / 折纸 / 信号（延续现有风格）

### 5.2 数据演示原语（待确认「CSV」含义）

如果指**数据可视化动画**（表格/图表/数字滚动/终端输出）：
`table-reveal`（逐行出现）、`bar-grow`（柱状生长）、`line-draw`（折线描画）、`number-roll`（数字滚动）、`terminal-type`（终端打字）、`cursor-blink`、`chart-axis`（坐标轴描画）
如果指 **CSS/代码类演示**（代码高亮、窗口弹出、终端日志），原语集改为：`window-open`、`code-type`、`highlight-line`、`log-scroll`、`progress-bar`、`status-badge`
→ 需用户确认后冻结原语表。

## 6. 模板商店（P2 实现，P0 定规范）

### 6.1 模板包规范（先定，后做商店）

```
template.dshpkg (zip)
├── manifest.json      # id, name, author, version, schemaVersion, 兼容编辑器版本, 分类/标签, 许可
├── template.ir.json   # anim-ir（纯数据，禁止可执行代码）
├── assets/            # 图片/字体/音频（可选；缺省回落）
├── preview.png        # 封面
└── preview.mp4        # 预览（可选，≤5s）
```

- 上传前校验：schema 合法、版本兼容、素材白名单、无脚本、包体积上限
- 下载安装：解压 → 校验 → 存入模板库；版本不兼容时提示「升级编辑器」

### 6.2 商店功能

上传 / 下载 / 搜索 / 分类标签 / 作者页 / 收藏 / 评分（1–5 星）/ 评论 / 举报 / 版本历史 / 兼容性标识 / 安装量排序 / 精选

### 6.3 后端方案（回答「NAS 能不能用」）

可以，但建议**分阶段**，别一步到位直接公网：

| 阶段 | 方案 | 适用 | 风险 |
|---|---|---|---|
| **P0 本地** | 不上传，只做「模板包导出/导入 + 本地模板库 + 分享链接（网盘）」 | 第一版/内测 | 无 |
| **P1 私有 Beta** | 威联通 NAS：Container Station 跑 API + Postgres/SQLite + 对象存储目录；公网走 **Cloudflare Tunnel**（无需公网 IP）或 **Tailscale**（只对邀请用户） | 小圈子邀请 | 家宽上行带宽、备案、稳定性 |
| **P2 公开** | 迁云：对象存储（R2/B2/S3）+ CDN + Serverless/轻量 API + 审核后台 | 公开 | 成本/合规/运维 |

QNAP 具体落地（P1）：
- Container Station：`store-api`（Node/Fastify）+ `postgres`（或 SQLite 落盘）+ 文件目录（NAS 卷）+ `cloudflared`（隧道，不暴露端口）
- 反向代理：QNAP 自带 Web 服务器/Caddy 容器；HTTPS 由 Cloudflare 或 Let's Encrypt
- 安全：关闭默认 admin、强密码、关 UPnP、只开隧道、快照 + 定时备份到第二块盘/异地
- 带宽估算：模板包 ≤20MB；1Mbps 上行 → 约 0.05 个/秒；家宽 30Mbps 上行可撑小规模内测
- **合规提醒**：境内 NAS 对外提供网站/下载/评论服务，理论需 ICP 备案与 UGC 内容审核义务；家庭宽带暴露公网还有被扫/被 DDoS 风险。建议 P1 先只做「邀请制/内网穿透给熟人」，P2 公开时迁云

### 6.4 商店安全与合规

- 纯数据模板（禁止可执行 JS/脚本）；素材版权声明；举报下架；审核队列
- 评论：敏感词过滤 + 举报 + 人工；账号体系（邮箱/第三方登录）
- 隐私：最小化收集；用户 key 永不入库
- 版权：商店规则明确禁止上传复刻他人作品的模板；参考视频复刻仅限本地自用

## 7. 还缺什么（回答「蓝图还缺什么」）

按优先级：

**P0 必补**
1. **模板包规范 + 导出/导入/版本迁移**（现在蓝图只到 schema v3，没有"包"和"兼容矩阵"）
2. **导出与启动播放器的契约**（模板 JSON 被插件消费；编辑器改动后如何回写、如何预览真实启动效果）
3. **Agent 事件协议 + 命令总线 + 操作日志回放**（§1.4）
4. **MCP 工具契约 + 权限分级 + 认证**（§2）
5. **失败兜底**：素材缺失/字体缺失/模型失败/超时/崩溃恢复（v1 有部分，需扩到 Agent/导出）
6. **性能预算与降级**（10 分钟项目、30fps 默认；短片 60fps；30 图层；WebGPU→WebGL2→Canvas2D）

**P1 应补**
7. **账号体系**（商店需要；本地默认不登录）
8. **审核与内容安全**（商店 UGC、评论）
9. **遥测/崩溃报告**（本地匿名、可关）
10. **安装包与自动更新**（编辑器随插件发还是独立安装包）
11. **i18n 与无障碍**（至少中英 + 键盘全操作）
12. **测试策略落地**：黄金帧、MCP 契约测试、Agent mock（不依赖真实模型跑 CI）、参考复刻 E2E

**P2 以后**
13. 商店评分/评论的运营后台
14. 模板商业化（付费模板/抽成/许可）
15. 多语言模板与语音字幕
16. 与剪映草稿互通（社区已有 pyJianYingDraft 生成/解析，https://github.com/wqeqwedq/pyJianYingDraft）
17. MCP 市场/外部 Agent 生态接入

## 9. 待确认（用户拍板）

1. **「CSV 这类动画演示」**具体指数据可视化（表格/图表/数字滚动/终端）还是 CSS/代码演示？决定原语表。
2. **60s 是硬上限**还是可配置（如模板级）？默认工程时长 10s 可以吗？
3. **商店首发范围**：只做邀请制内测（Tailscale/局域网）还是直接公网（NAS + 隧道）？决定备案与安全动作。
4. **DSH 联动形态**：编辑器内 Agent 面板默认用本机 DSH；「单独上下文窗口」是 DSH 新建会话，还是编辑器右侧独立 chat？（建议前者做解释、后者做执行）
5. **模板包导出**是否需要同时支持「引擎 JSON（启动播放器用）」和「视频文件」两种？启动播放器当前吃的是哪种？
6. **MCP 首发客户端**：只需 DSH，还是同时支持 Codex CLI 等外部 MCP host？
7. **账号体系**是否首发就做（没有账号，商店评论/评分很难成立）？
8. **参考视频复刻**的版权规则：是否只允许用户自己的作品/授权素材？商店模板是否禁止复刻内容？

## 15. 时间线冗余决策（D13，已拍板）

**决定：留冗余，但分层，不做成用户可见的 11 分钟。**

## 17. 音频方案（D17：Fairlight 精简版，P0 与画面同级）

**定位**：工具尽量全，但**不追求专业级**；目标是「非音频专业的用户也能把声音处理好」。声音与画面同级，不是后期补的附属功能。

### 17.1 轨道
- 视频轨 1 条 + **音频轨 N 条**（默认 3：BGM / 配音 / 音效；可增删）；
- 每轨：音量推子、声像（pan）、静音（M）、独奏（S）、波形、片段淡入淡出、拖拽对齐/吸附；
- 片段级：剪切、复制、增益、静音、淡入淡出、音量自动化（P2）。

### 17.2 总线（参考 Resolve Fairlight 的信息结构，不抄 UI）
- **Track Bus**：每轨可路由到总线，可建 1–2 条总线（如 BGM 总线、对白总线）；
- **Master Bus**：总输出，带：音量、**三段 EQ**、**压缩器**、**限幅器（防爆音，默认峰值 -1 dBFS）**、电平表（Peak/LUFS 简版）；
- 批量处理：选中「整轨/选中片段/全部」→ 统一增益、归一化、降噪（轻）、淡入淡出，一键应用。

### 17.3 声音来源
- **导入**：本地音频（mp3/wav/m4a/flac）；
- **合成**：内置「音乐合成/曲库」占位（第一版先用 UI 音效库 10 个 wav + 预留 provider 接口，后续接第三方曲库/TTS）；
- **配音**：导入 / 浏览器录音（M2）/ TTS（M3，接 AI provider，占位）。

### 17.4 混音与导出
- 48kHz / 立体声；AAC 导出；音量单位 dBFS；
- **自动 ducking**：人声/配音出现时 BGM 自动降 3–6 dB（可调、可关）；
- 导出前「响度检查」：峰值超 -1 dBFS 提示，可选一键归一化到 -14 LUFS 附近（按平台可调）。

### 17.5 UI
- 时间线下方新增**音频面板**：每条音频轨一行（波形 + 轨道头：名字/推子/pan/M/S）；
- 右侧面板可切「音频总线」：Track Bus / Master Bus 的 EQ/压缩/限幅参数；
- 选中片段显示「片段音频设置」：增益、淡化、路由到哪条总线；
- 参考：用户可提供 Resolve 参考手册（Fairlight 页），作为**信息结构参考**，不自造一套没人看得懂的专业界面。

### 17.6 分阶段
- M1：轨道 + 音量/pan/M/S + 淡入淡出 + 导入/合成 + 波形；
- M2：总线（EQ/压缩/限幅）+ ducking + 批量处理 + 响度检查；
- M3：音量自动化曲线、录音、TTS、更细的批量处理器。

### 17.7 参考 Fairlight 的信息结构（已读 Resolve 手册 chapter 170–184）

官方 Fairlight 页的 8 个信息块（我们只取简化版）：
1. 顶部工具条（选择/剪切/自动化/吸附）；
2. 音频时间线（波形、轨道头、缩放/波形高度、播放头、标记）；
3. 混音台 Mixer（每轨 channel strip：输入/输出路由、inserts、EQ、dynamics、fader、pan、M/S）；
4. Inspector（选中片段/轨道的详细参数）；
5. Bus 路由（FlexBus：track→bus、bus→bus、bus→master）；
6. 音频表与监听（电平表、监听选择）；
7. 自动化（volume/pan/EQ 曲线）；
8. 分组（Track Groups）。

**我们精简为**：时间线音频行 → 混音台条 → 总线（Track Bus / Master）→ 检查器 → 电平表 → 自动化（P2）。**不做**：环绕声 pan、2000 轨、Dolby Atmos、ADR——不需要。

## 18. 商店方案改为 GitHub-native（D20，覆盖原 §18 占位方案）

**策略**：整体学习 dsh-market——**不自建服务器、不自营账号、不做评论**，直接调用 GitHub 仓库（与 dsh-market 同一路线）。

- **模板仓库**：**一个模板一个 GitHub 仓库**（推荐；star 天然按模板计）。仓内：`template.json` + `assets/` + `preview.gif` + `demo.mp4` + `README.md` + `LICENSE`。
- **Registry 仓**（我们维护）：`dsh-editor-templates` 仓，存 `templates.json`（条目：id/name/author/repo/version/tags/preview/demo/star 缓存/schemaVersion/兼容区间/license）。作者提 PR 申请收录。
- **审核流水线**：PR → 自动检查（结构/schema/大小/无脚本/预览图/视频）→ **AI 代码审查（我来）** → **人工肉眼看视频（你来）** → 合并；驳回给原因模板。
- **评分**：只做星级 = 模板仓库的 GitHub star；**每小时**由 GitHub Action 拉 stars/forks/updated 更新 `templates.json`（静态文件）；编辑器读 raw JSON（ETag + 1 小时缓存），不实时打 GitHub API（避开限流）。
- **修改/派生**：用户改模板 → fork 作者仓库 → 作为新模板（新 PR 收录）；作者合并则回馈上游。
- **上传要求**：作者必须提供 **≥480p、25/30fps 的完整演示视频**（建议 10–60s、≤100MB），另存预览 GIF（3–5s，≤500KB）；模板资产 ≤20MB。
- **账号**：彻底放弃自营账号，**用 GitHub 身份**（提交/PR/fork 即身份）；商店显示作者 GitHub 头像/昵称。
- **无服务器**：客户端只拉 GitHub raw（registry JSON、preview.gif、demo URL）；评论/打分不做；安装量不做（无法准确统计）。
- **下架/举报**：作者删仓 → registry 标记 unavailable；举报走 GitHub issue。
- **占位**：编辑器保留「商店」入口与 service 地址配置；本地模板库先跑通，未来接 GitHub registry 只换数据源。
