# DSH 大版本升级兼容性检查清单

> 适用：DSH 大版本更新（如 0.2.1-rc.x → V5）或小版本更新后，5～10 分钟确认 dsh-boot-suite 与第三方插件是否正常。
> 原则：**先备份、先诊断、再升级插件**；升级当天不与插件更新/灵枢更新叠加。
> 相关文件：`tools/doctor.ps1`（一键诊断）、桌面「紧急回滚-V…」bat、崩溃日志目录 `%APPDATA%\@deepseek-ai\dsh-desktop\logs\`。

---

## 0. 升级前（1 分钟）

- [ ] 记录当前版本：DSH 版本 + 插件版本（设置页底部/诊断报告）
- [ ] 确认桌面有**最新的「紧急回滚-V<上一版>」bat**；没有就先跑一次安装器生成
- [ ] 备份 `~/.dsh/dsh-startup.json`、`~/.dsh/chat-wallpaper.json`（用户配置，绝不重置）
- [ ] 确认 DSH 完全退出（窗口 + 托盘）后再装新版本
- [ ] **不要**在同一天更新 DSH 和插件；先 DSH，观察正常后再考虑插件

## 1. 升级后 5 分钟快速检查（按顺序）

### 1.1 进程与版本
- [ ] DSH 能正常打开，无 `DeepSeek Harness is unavailable` 弹窗
- [ ] 设置页能看到 **「启动动画」** 与 **「聊天背景」** 两个入口
- [ ] 插件版本显示正确（当前发布版；不是「未安装」或空）
- [ ] 任务管理器里没有重复的 DSH 进程堆积

### 1.2 profile 与插件清单
```powershell
# junction 指向的包路径与版本
(Get-Item "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-boot-suite").Target
Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\package.json" -Raw | ConvertFrom-Json |
  Select-Object -ExpandProperty dependencies
```
- [ ] `dsh-boot-suite` 指向 `~/.dsh/boot-suite-updates/<版本>/pkg`
- [ ] profile `package.json` 依赖里有 `dsh-boot-suite`，`dsh.profile.bundles` 含它
- [ ] 没有 `cannot resolve profile bundle` 报错

### 1.3 启动动画（冷启动一次）
- [ ] 六幕动画完整播完，无黑屏/卡死；`SKIP` 可跳过
- [ ] 第一幕英文配音（默认音色F + 机器人效果）正常
- [ ] 日文音色切换后正常；声音效果可切换
- [ ] 终幕欢迎语延迟正常（05→06 和声钟后进入）
- [ ] 三段转场生效（入口/换场/退场），默认交叉叠化
- [ ] 结束后正常落到聊天界面

### 1.4 聊天背景
- [ ] 静态底图 + 循环视频都能显示；「刷新」按钮有结果反馈
- [ ] 图片适配（铺满/完整）正常
- [ ] 色彩模式（彩色/黑白）正常
- [ ] 纱浓度、镜头模糊滑块生效，且**不联动**
- [ ] 深色/浅色外观切换后：聊天正文、侧边栏、输入框、标题栏窗口按钮均可见

### 1.5 更新与诊断链路
- [ ] 设置页「检查更新」能拿到最新版本号
- [ ] 「生成诊断报告」**点一次只生成一份**，按钮进入「生成中…」
- [ ] 更新等待页有进度/超时提示（30 分钟）、「打开下载文件夹」「选择安装包」
- [ ] 安装器生成新的紧急回滚 bat，并清理旧按钮

### 1.6 失败即停
任一项失败 → 不要继续更新插件；先收集：
- [ ] 设置页「生成诊断报告」文件（桌面）
- [ ] 崩溃日志（若有）：`%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-*.log`
- [ ] DSH 控制台窗口报错截图

## 2. V5 专项预判（官方内置插件市场 / 记忆互通）

- [ ] 第三方 `dshmarket` 仍能正常打开、安装/更新插件（官方市场若上线，两者可能并存或替代）
- [ ] `@furongjun1999/dsh-memory`（灵枢）能加载，记忆写入/召回正常
- [ ] 若官方记忆互通启用：
  - [ ] system prompt 中**没有两个重复的「记忆/上下文」块**
  - [ ] 没有同一记忆被两套机制重复注入导致超长
  - [ ] 工具名无冲突（两边都注册 `memory_*` 类工具时）
  - [ ] 出现冲突时，先关灵枢的 `autoRecall` / `contextWindow` 再观察，不要直接卸载
- [ ] 插件 API 变化扫描：
  - [ ] `dsh.profile.bundles` / `dsh.bundle.patch` 清单格式仍兼容
  - [ ] `ctx.webServer.register` / `tapIndex` 仍可用（开机动画注入依赖它）
  - [ ] 前端注入点（client bundle、设置页 Slot）仍存在
  - [ ] 插件管理器行为（是否仍拒绝原地升级、安装源/镜像设置）

## 3. 出问题时的恢复顺序

1. 完全退出 DSH（窗口 + 托盘；必要时任务管理器结束全部 DeepSeek 进程）
2. 双击桌面 **「紧急回滚-V<上一版>」**，等日志完成，手动打开 DSH
3. 回滚仍打不开 → 用 `03-发布包` 对应版本 zip 重新解压安装，或运行 `tools/emergency-uninstall.ps1`
4. 把诊断报告 + 崩溃日志发给作者；记录到交接文档「事故记录」
5. **不要**循环重启、不要让脚本自动启动 DSH
