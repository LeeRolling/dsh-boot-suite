# 自动更新：需求与决策（已拍板）

> 状态：**等待用户更新 DSH 客户端**，更新完成后再开始实现。
> 原因：DSH 更新可能改变 DOM/启动方式（caption-probe 已经出现 *_frame 结构变化），
> 自动更新涉及"关闭客户端→替换文件→重启"，必须在新版 DSH 上观察后再做。

## 已确认的 5 条规则

1. **更新范围**：只更新插件本体；只备份配置，不覆盖用户配置
2. **检查频率**：每日一次（+ 手动可点）
3. **失败策略**：
   - 自动回滚到上一版
   - 提示一次，不自动重试
   - 自动在桌面生成诊断报告
   - 弹窗文案：「请把桌面生成的诊断报告，私聊给制作者。」
4. **跳过版本**：支持（用户可自主选择不更新某个版本）
5. **更新通道**：只连 GitHub 最新 Release，不做 beta

## 更新流程（用户视角）

1. 检查到新版本 → 显示更新内容 → 用户点【立即更新】
2. 下载安装包（进度条，可取消）
3. 下载完成、校验通过 → 弹窗：
   「本次更新需要重启 DSH。请确认没有正在进行的对话。是否现在重启？【是】【否】」
4. 点【是】→ 自动关闭 DSH → 更新窗口（校验/备份/安装/健康检查）→ 自动启动 DSH
5. 失败 → 回滚旧版 → 启动 DSH → 提示失败 + 诊断报告已生成

## 技术要点

- 插件不能自己"关闭自己再替换自己"：必须启动一个**独立更新脚本**，由它等待 DSH 退出、安装、重启
- 更新窗口先用 PowerShell 文字进度；后续可换小窗口
- 健康检查：新版首次启动写成功标记；无标记则回滚
- 需要真机测试多次（自动关闭/启动路径因机器而异）

## 分阶段

| 阶段 | 内容 | 估计 |
|---|---|---|
| 1 半自动 | 检查 + 下载 + 【是/否】+ 外部脚本等待关闭/安装/重启 | 1 天 |
| 2 完整版 | 更新窗口进度 + 备份 + 健康检查 + 失败回滚 | 1–2 天 |

## 下次开工前要确认

- 用户已更新 DSH 到哪个版本
- 新版 DSH 下：启动动画、聊天背景、设置页、诊断按钮是否正常
- caption-probe 的新结构（cornerStack / frameEls）是否已拿到
