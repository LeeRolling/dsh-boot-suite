# 主线总结：代码模板 / 许愿式流水线（2026-10-25）

> 这份文档只讲主线，不涉及已发布插件的日常维护（那部分见 `docs/交接-插件维护.md`）。

## 1. 主线是什么

长期目标：**许愿式动画**——任何 AI（DeepSeek / Claude / 其他）读了《代码模板规范》，写出一套代码模板；我们的**校验器 + 渲染器**把它变成可安装、可播放的开机动画。

拆成四段：

1. **规范**：`docs/code-motion/01-代码模板规范-v0.1.md` + v0.2 增补
2. **参考实现**：Remotion 工程 `09-技术验证-remotion`（不是最终产物，是“渲染器原型”）
3. **校验**：结构 / 时间轴 / 色彩字体 / 确定性 / 质量指标（v0.2）
4. **落地**：转成插件模板（`templates/<id>/template.json` + 资源），装进 dsh-boot-suite

## 2. 两轮与 Claude 的学习

### 第一轮：SuperX 15 秒全片

- 同一命题分别做 15s 科技感开场，Claude 独立交付多文件实现。
- 结果：Claude 版完成度高、镜头语言完整；我们复刻时把 SuperX 拆成 750 帧 / 50fps 并在 Remotion 里渲染成 `out/superx-claude-full.mp4`。
- 学到：Claude 会自己建立稳定结构（tokens / parts / shot 文件）、每个镜头独立、Main 只负责装配；会写自检与取舍。

### 第二轮：SIGNAL 12 秒命题（正式验证）

- 同一份命题 + 同一份 v0.1 规范，不告诉 Claude 这是规范测试。
- Claude 回复 650 行：分镜表 + 7 个文件（tokens / parts / Main / 4 个 Shot）+ 自检 + 风险；我们拆分、修掉末尾混入的过程日志、在 Remotion 注册并**一次渲染成功**（600 帧，2.79MB）。
- 对比：Claude 加权 **4.7 / 5**，我的 V1 **2.9 / 5**；客观指标：V1 近黑帧 32%、平均亮度 9.4；Claude 近黑帧 0%、平均亮度 12.9。
- 产物：`09-.../out/signal-claude.mp4`、`out/signal-v1.mp4`、`docs/code-motion/validation/对比结论.md`、`validation/claude-signal/`。

## 3. 我具体学到了什么

### 3.1 结构上（可直接照抄的做法）

- `tokens.ts` 集中：分辨率/帧率/颜色/字体/缓动/时间轴/文案/全局帧 helper。
- 一个镜头一个文件，`Main.tsx` 只做 Layer + Sequence 装配。
- Sequence 之间**刻意重叠 0.4–0.6s**，交界处元素自己淡出，避免硬切。
- `useGlobalFrame(startSec)` 把 Sequence 局部帧还原成全局帧，所有时间常量写“全局秒”。
- 跨镜头同一个元素连续位移（准星→雷达中心），而不是各画各的。

### 3.2 交付上

- 必交：分镜表（时间/动作/缓动/**退场/重叠**）、ASSUMPTION 编号、自检表、风险清单。
- 自检必须包含“已渲染 + 联系表 + 关键帧目视”，否则交付不算完成。
- 文件块要有明确结束标记；Claude 这次在最后一个文件后混入“过程日志”，提取时被迫手工截断——交接协议要收紧。

### 3.3 质量上

- 科技感不等于“黑底 + 小字 + 大留白”；**画面密度、明度层次、主体占屏**决定第一眼。
- 网格负责秩序；准星/雷达负责叙事焦点；面板负责信息量；粒子/描边负责收束。四者缺一就单薄。
- 字体不打包会同时拉低双方质感（Inter / JetBrains Mono 缺失），这是工具链问题，不是规范问题。

### 3.4 工程上

- Remotion 适合做**参考渲染器**：Claude 代码只需注册 Composition 即可验证，不需要改业务逻辑。
- Canvas/异步资源必须 `delayRender` / `continueRender`，不能依赖 `useLayoutEffect` 的偶然时序。
- 确定性：禁用 Math.random / Date.now / setTimeout / CSS animation；随机只用 seed。

## 4. 怎么用到下一步视频设计

### 4.1 先定“质量门槛”，再谈创意

下一支视频开工前先写 4 个数字：

1. 平均亮度 ≥ 10（0–255）
2. 近黑帧（Y<8）≤ 5%
3. 任意 1s 内至少一个可辨认主体
4. 关键主体短边 ≥ 画面短边 18%

这四条直接进 validator；不达标不进入安装环节。

### 4.2 分镜模板固定列

`时间 | 元素 | 入场 | 停留 | 退场 | 与前后镜头重叠`——没有“退场+重叠”两列的分镜，不接受。

### 4.3 流水线（下一步要做的）

```
AI 输出（严格文件块/zip）
  → 解析 + esbuild/tsc 编译
  → Remotion 渲染 mp4 + 1fps 联系表 + 关键帧
  → validator：结构/时长/色彩字体/确定性/亮度/空屏/主体占屏/交付物齐全
  → 评分门槛（结构≥4、交付≥4、质量指标达标）
  → 转插件模板（JSON layers / 视频模板）→ 安装
```

### 4.4 下一支视频的设计要点（从两轮学习直接迁移）

- 开头 1s 必须出现“可读主元素”（V1 的教训：前 4s 空黑）。
- 每 2s 至少一次“信息升级”：新数字、新状态、新焦点。
- 相邻镜头重叠过渡；跨镜头主角连续。
- 只做 1 次故障/闪白，时长 ≤0.3s，位置放在结构转折点。
- 片尾 hold ≥0.8s，标题/副标题/域名三件套。
- 先写 tokens 与分镜，再写镜头；最后统一在 Main 装配。

## 5. 我的差距（诚实记录）

- V1 的问题不是“不会写代码”，是**没有质量底线和自检纪律**：文件结构对、元素齐，但画面空、亮度低、交付缺 ASSUMPTION 和分镜细节。
- Claude 的优势不是“更会写”，是**流程完整**：先分镜、再 tokens、再逐镜、最后自检与风险。
- 所以下一轮我的角色要从“写代码的人”变成“定标准 + 做校验器的人”。
