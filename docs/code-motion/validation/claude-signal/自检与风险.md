// 闭式运动：任意帧直接算出位置，不依赖上一帧；弧线靠垂直方向的正弦偏移
const place = (p: Pt, e: number) => {
  const dx = p.tx - p.x0, dy = p.ty - p.y0, len = Math.hypot(dx, dy) || 1;
  const b = p.bow * Math.sin(Math.PI * e);
  return [p.x0 + dx * e + (-dy / len) * b, p.y0 + dy * e + (dx / len) * b] as const;
};

const draw = (ctx: CanvasRenderingContext2D, g: number) => {
  ctx.clearRect(0, 0, W, H);
  const t = g / VIDEO.fps;
  const vis = ramp(g, 8.5, 8.75, 0, 1) * (1 - ramp(g, 9.9, 10.3, 0, 1));
  if (vis <= 0) return;
  PARTS.forEach((p) => {
    const raw = (t - 8.5 - p.d) / p.dur;
    const e = EASE.out(clamp01(raw));
    ctx.fillStyle = p.orange ? COLOR.orange : COLOR.white;
    if (e > 0.02 && e < 0.98) {
      for (let k = 2; k >= 1; k--) { // 短拖尾
        const [qx, qy] = place(p, EASE.out(clamp01(raw - 0.07 * k)));
        ctx.globalAlpha = (p.a * vis * 0.3) / k;
        ctx.fillRect(qx - p.s / 2, qy - p.s / 2, p.s, p.s);
      }
    }
    const [x, y] = place(p, e);
    ctx.globalAlpha = p.a * vis;
    ctx.fillRect(x - p.s / 2, y - p.s / 2, p.s, p.s);
  });
  ctx.globalAlpha = 1;
};

  position: 'absolute', left: 0, width: W, top: y - h / 2, height: h, display: 'flex', justifyContent: 'center', alignItems: 'center',
});

3. 过程日志

为什么这样拆分

5 个组成部分：Backdrop（常驻层）、Shot_Capture、Shot_Analyze、Shot_Reticle、Shot_Resolve。
准星单独成镜头：它从捕获段到分析段是同一个物体，会平移变成雷达中心。如果各画各的，交界处会"重置"，就看不出连续性。
Sequence 刻意重叠 0.4–0.6s：硬切时元素会突然消失；重叠后每个元素自己淡出。
时间常量写全局秒：useG 把局部帧还原成全局帧，改节奏时不用做减法。

镜头	动画原语	为什么选它
Backdrop	多层 linear-gradient 网格 + mask-image 径向淡出 + background-position 匀速漂移	网格不需要任何节点，一层 div 搞定；漂移只改背景位置，不触发重排
Capture	SVG pathLength=1 + strokeDashoffset 描边；clip-path: inset 揭开刻度尺；slice 打字机；blink 用 floor(g/25)%2	描边是矢量不糊；打字机是阶梯函数，天然确定
Reticle	4 条 line 外延 + 圆环描边 + 一条 path 画 36 个刻度	一条 path 比 36 个 line 节点省
Analyze	CSS perspective + rotateY；polyline 波形；conic-gradient 扫描 + 三角函数算回波衰减	平面面板用 CSS 3D 就够，文字最清晰；扫描衰减用 exp(-Δ角/110)，每帧直接算
Resolve	Canvas 2D 粒子（闭式运动）；SVG 描边；clip-path wipe	粒子位置是 lerp + 垂直弦偏移，可随机 seek，不依赖上一帧
故障	GlitchText：4 切片 clip-path + 橙/灰蓝重影	重影只用调色板里的两种颜色，不引入 RGB 纯色，守住 ≤4 色

取舍

故障只放在计数上，没有做全画面故障。理由：规范只要求"一次"，且全屏故障的重影颜色会超出调色板。
粒子用 Canvas 而不是 SVG 圆：220 个 SVG 圆也能做，且没有 canvas 绘制时机的风险；我选 Canvas 是因为你之前的规范里粒子固定走 Canvas 2D。
没有加噪点/扫描线：feTurbulence 逐帧计算代价高，而且暗部色带的问题我没法在这里验证，所以先不加，列入风险。
缓动之外用了匀速：打字、扫描、网格漂移用线性，已在 tokens 里标注。
面板阴影用低透明度的灰蓝光晕，没有用纯黑阴影，因为纯黑会算第 5 种颜色。

ASSUMPTION 列表

节点坐标、刻度尺位置、面板尺寸、雷达半径：构图是我定的，没有参考依据。
粒子数量 220、拖尾 2 级、弧线幅度 ±80px：凭经验估计。
文案（COPY）是占位文案；signal.example 是保留域名，发布前请替换。
字体：假设本机装有 Inter 和 JetBrains Mono，回退字体宽度不同，文字位置会偏移。
2 帧一变的故障节奏（25Hz）：我没看过实际渲染，不确定在 50fps 下观感是否合适。

如果只能再改一处：让粒子从面板和雷达的真实位置散出来，而不是全屏随机起点。现在 8.5s 的"物体 → 粒子"转场靠闪白遮过去，缺少因果；起点改成面板边缘和雷达圆周，转场才会可信。

5. 风险
字体：必须在第一帧之前加载好。回退到 Arial 后，「87%」和标题宽度会变，居中会偏。tabular-nums 只对支持该特性的字体有效。
性能：conic-gradient 全幅 300×300 + 网格 mask 每帧重算；波形 90 点 × 2 条 polyline；Canvas 220×3 次 fillRect。单帧应该在预算内，但 mask 叠 gradient 在某些机器上偏慢，要实测。
确定性：
最大风险是 Canvas：useLayoutEffect 里画，截图前必须已绘制完成；如果出现"首帧空白"，改成 delayRender / continueRender。
浮点：Math.sin / Math.exp 在同一机器上确定，跨机器可能有极小差异，对像素基本无影响。
暗部色带：深底 + 低透明度网格 + 径向光晕，在 H.264 下很容易出现台阶。建议渲染时 --crf 16，必要时给背景加极轻噪点。
3D 面板文字：rotateY 过程中文字会被重新栅格化，翻入前半段可能发糊，属于预期。
标题居中：靠 paddingLeft: 0.3em 抵消末尾字距，换字体或字距后要重新核对。
