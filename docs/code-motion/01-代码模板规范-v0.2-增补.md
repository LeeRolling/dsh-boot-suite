# 《代码模板规范》v0.2 增补（SIGNAL 验证后）

> 来源：`validation/对比结论.md`。只增补被 SIGANL 验证暴露的缺口，不推翻 v0.1。
> 原则：规范既要“可执行”，也要有“质量下限”；否则会出现“结构全对但画面看不见”的合格废片。

## A. 可读性底线（新增，硬性）

A1. **任意 1 秒区间内，画面必须至少有一个可辨认主体**（标题/面板/准星/图形），不得出现“只有背景网格/近黑”的连续空屏。
A2. **亮度下限**：全片平均亮度不得低于 10（0–255），近黑帧（Y<8）占比 ≤5%。
A3. **主体占屏**：关键信息主体（面板/标题/准星）短边不小于画面短边的 18%，不得靠“小字+大留白”撑科技感。
A4. 暗色主题允许，但必须有 2 级以上的明度层次（底/中景/主体），不能整屏同一灰度。

## B. 镜头与转场（新增）

B1. 相邻镜头**交叠 0.4–0.6s**，交叠处由元素自行淡出，**禁止被 Sequence 硬切**。
B2. 分镜表必须增加两列：**退场方式**、**与前后镜头重叠区间**。
B3. 跨镜头同一元素（如准星→雷达中心）必须连续位移，不允许“各画各的然后重置”。

## C. 交付与自检（强化）

C1. **交付前必须实际渲染**：mp4 + 1fps 联系表 + 3 张关键帧；自检表里要写渲染路径与“已目视”。
C2. **ASSUMPTION 逐条编号**；缺一条视为交付不合格（v0.1 只写“标注”，没写“不合格”）。
C3. **文件块格式**：每个文件用 `=== FILE: x ===` 开始、`=== END FILE ===` 结束；禁止在最后一个文件后混入说明文字（本次 Claude 回复末尾混入“过程日志”，导致提取需要手工截断）。
C4. 自检表必须含“与分镜表逐项对应”检查，不能只列条款打勾。

## D. 时间轴与框架（补约定）

D1. tokens 里统一提供 `useGlobalFrame(startSec)`（Sequence 局部帧 → 全局帧），所有镜头只写全局秒。
D2. 时间常量（镜头起止、重叠、事件点）必须集中在 tokens 的 `TL` 里，禁止散落在各镜头。
D3. 缓动只允许 4 种命名曲线 + LINEAR；线性必须显式标注（本次 Claude 做对了）。

## E. 确定性（补风险）

E1. Canvas / 图片 / 字体等异步资源，必须用 Remotion `delayRender` / `continueRender`，禁止依赖 `useLayoutEffect` 的偶然时序。
E2. 字体不打包时必须做“回退字体版式测试”：关键标题/计数在 Arial/系统等宽下不得溢出或错位。
E3. 渲染参数写进交付：`--crf 16–20`、faststart；暗部色带需在联系表上检查。

## F. 评分口径（补客观项）

F1. 质感分之前先跑客观指标：平均亮度、近黑帧占比、主体占屏率、联系表可读性。
F2. 工具链导致的问题（字体/3D/粒子库）单列“工具链分”，不混入“规范分”。
F3. 交付分低于 4 时，其余分不得作为“规范通过”的依据。

## 一句话

v0.1 解决了“AI 能不能写出结构正确的模板”；v0.2 要解决“写出来的东西能不能看”。
