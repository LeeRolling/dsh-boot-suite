## A. 目标与成功标准

### A.1 许愿式是什么

用户对任何 AI「许愿」一段动画 → AI 读《代码模板规范》写出代码模板 → **validator 静态检查 + 画面指标** → **Remotion 渲染** → **转成可安装模板** → 装进 `dsh-boot-suite` 插件。目标是让「任何人 + 任何 AI」都能产出**结构正确、画面可看、可安装**的开机动画，而不是靠我们手写。

### A.2 成功标准（分层）

| 层级 | 判据 | 现状 |
|---|---|---|
| 规范可执行 | 外部 AI 只拿「命题 + 规范」就能独立交出可渲染、元素全覆盖的文件结构 | **已达成**：Claude 的 SIGNAL 与 ORIGAMI 都只靠命题 + 规范完成 7 文件交付，由我们代渲染成功 |
| 质量有下限 | validator 对结构 / 交付 / 画面三类硬项全过才 PASS，不达标不进入安装 | **部分达成**：SIGNAL 有 PASS / FAIL 对照；ORIGAMI 有命题包、v3 已 PASS 16/16，但命题包对 Claude 提交只认 10/16（见 F.4 / H-2） |
| 许愿式闭环 | 随机出题 → AI 写模板 → 自动校验 → 渲染 → 转模板 → 安装，全程少人工 | **未达成**：转模板未开工；validator 还不能验证「真的渲染过」 |
| Bible v1.0 | 每轮随机命题，人工审核（我方 vs Claude）差距 **< 20%** | **未达成**：ORIGAMI 只有客观指标对比（v3 更亮更空、墨色信息偏少），6 维加权分未打（**待确认**） |

### A.3 不能混淆的两个「成功」

- **结构分 ≥4 / 5** 只证明规范可执行；**交付分 ≥4 / 5** 只证明交接协议可执行（`validation/对比计划.md` 的验收口径）。
- 质感低先归**工具链**（字体 / 3D / 粒子库），不归规范；否则会把工具问题写成规范条款，越写越虚。v0.2 F2 已把这条固定。

## D. 多轮 Claude 学习（每轮：1 条规范 + 1 条 validator 规则 + 1 条设计规则）

### D.0 第零轮：SuperX 15 秒（热身）

同一命题各做 15s 科技感开场，Claude 独立交付 8 文件 / 750 帧，我们复刻并渲染成 `out/superx-claude-full.mp4`（3.12MB）。学到：**结构可复用**（tokens / parts / 每镜一文件 / Main 装配），Claude 自带自检与取舍。归档在 `docs/code-templates/superx-full-15s/`。这一轮没有正式评分。

### D.1 第一轮：SIGNAL 12 秒（正式验证 v0.1）

- 命题：`validation/SIGNAL-命题.md`（12 个必含元素、1280×720/50fps/600 帧、≤4 色 ≤2 字体、禁随机/定时器）。
- 做法：同一命题 + 同一份 v0.1，**不告诉 Claude 这是规范测试**（用户修订版提示词，避免应试）。
- 交付：Claude 约 650 行、7 个文件（tokens / parts / Main / 4 个 Shot）+ 分镜 + 自检 + 风险；我们拆分、修掉末尾混入的过程日志、注册 Composition，**由我们一次渲染成功**（2.79MB）。
- 结果：加权 **Claude 4.7 / 我方 V1 2.9**（满分 5）；客观：V1 近黑帧 32%、平均亮度 9.4；Claude 近黑帧 0%、平均亮度 12.9。
- 学到的四件事：
  1. **质量下限缺失**：V1 结构全对、元素齐全，但前 4s 空黑——规范只约束「有没有」，没约束「看不看得见」→ v0.2 A。
  2. **转场纪律**：Sequence 之间重叠 0.4–0.6s、元素自己淡出，禁止硬切；分镜必须写「退场 + 重叠」两列 → v0.2 B。
  3. **交付纪律**：ASSUMPTION 逐条编号、文件块必须有 `=== END FILE ===`、交付前必须真渲染并目视 → v0.2 C。
  4. **框架约定**：`useGlobalFrame(startSec)`、时间常量集中 `TL`、缓动只允许 4 条命名曲线 + LINEAR → v0.2 D；异步资源必须 `delayRender` → v0.2 E。
- 另有一条常被忽略：**Claude 自检里明说「没有渲染过」**，却仍拿了交付高分。说明「要求渲染」如果没有机器检查，就只是口号。

### D.2 第二轮 / 第三轮：ORIGAMI 纸艺日出（换视觉语言）

- 命题：`validation/ORIGAMI-命题.md`（暖白纸面、折纸、剪纸山峦、墨线、活字、印章；与暗色 HUD 完全不同的实现路径）。
- Claude 交付：7 个文件 + 分镜（含退场/重叠）+ 过程日志 + 自检 + 风险；`src/origami-claude/原文.txt` 36KB 原文，开头第一句是「**我没有渲染**……这个环境里没有 Remotion」——它给不出 mp4 / 联系表 / 关键帧。
- 我方：v1 被「前 4 秒白屏、覆盖物迟迟不打开」打回，v2 修到能过 validator，但仍落后 Claude；v3 已按 v0.3 逐条重做并于 03:06 出片（PASS，见 G.3），并把新细则追加成 v0.3 的 H–O，人工验收待做。
- 学到的四件事 → v0.3：
  1. **揭示式转场**：先露主体再展开覆盖物，覆盖物要有方向与折痕 → v0.3 A（我方 v1 的白屏就是反例）。
  2. **跨镜头常驻主角**：太阳/地平线放在 Sequence 外，换段只变状态不重建 → v0.3 B。
  3. **分层质感**：山峦至少深 2 阶 + 1 条墨线；装饰必须服务叙事节点（日出/盖章/收尾），不能全程撒 → v0.3 C。
  4. **validator 要按命题配置**：能力关键词不能写死成 HUD，每题一份 brief pack；交付要查「顺序」；过程日志里的动画原语抽成词典 → v0.3 D/E。
- 机制沉淀：v0.3 F「三个一」——每轮必须产出 1 条规范 + 1 条 validator 规则 + 1 条设计规则；本轮分别是 A1、D1、B1。

### D.3 三轮共同结论

- Claude 的优势不是「更会写代码」，是**流程完整**：先分镜 → 再 tokens → 逐镜实现 → 自检与风险。
- 我方角色应从「写代码的人」变成「**定标准 + 做校验器的人**」。
- 它给不了渲染物，所以「先渲染再交付」这一环必须由我们兜底（见 I-3）。

## E. 规范现状速查

### E.1 v0.1 正文（不变的地基）

| 节 | 要点 |
|---|---|
| 1 组成 | tokens（颜色/字体/缓动）→ parts（可复用零件）→ shots（一镜一文件）→ main（装配）；**禁止一个文件写完整片** |
| 2 硬约束 | 1280×720 或 1920×1080；25/30/50/60fps；3–30s；≤4 主色、≤2 字体族；每帧是「第 f 帧」的纯函数；禁 CSS animation/transition、rAF、setTimeout、Math.random、Date.now；禁联网与外部字体/图片/视频；不复刻他人素材/品牌；随机必须固定种子 |
| 3 性能预算 | 同屏元素 ≤80；Canvas 粒子 ≤3000；SVG 节点 ≤500；blur ≤40px 且同屏 ≤3 层；禁全屏 backdrop-filter；不逐帧动 box-shadow/width/height/top/left（用 transform/opacity） |
| 4 交付 | 先分镜（时间/主角/动作/缓动），再文件，不确定标 ASSUMPTION，末尾给「需要核对的几处」，不写长篇解释 |
| 5 自检 | 总帧数 = 时长 × fps、Sequence 无空洞；秒→帧换算不写死帧号；一镜一主角、同屏动作 ≤3；文字落定停留 ≥0.8s；首末帧可定格；写清字体依赖与回退 |
| 6 许可 | 代码 MIT；参考作品版权归原作者，只学结构；字体只用开源可商用并注明 |

### E.2 v0.2 增补（A–F，SIGNAL 后）

- **A 可读性底线**：A1 任意 1s 内至少一个可辨认主体；A2 平均亮度 ≥10、近黑帧（Y<8）≤5%；A3 关键主体短边 ≥ 画面短边 18%；A4 暗色主题要有 ≥2 级明度层次。
- **B 镜头与转场**：B1 相邻镜头交叠 0.4–0.6s、元素自淡出、禁止硬切；B2 分镜加「退场方式 / 重叠区间」两列；B3 跨镜头同一元素连续位移。
- **C 交付与自检**：C1 交付前必须真渲染（mp4 + 1fps 联系表 + 3 张关键帧，写路径 + 已目视）；C2 ASSUMPTION 逐条编号，缺一条即不合格；C3 文件块用 `=== FILE: x ===` / `=== END FILE ===`，末尾不得混说明；C4 自检要与分镜逐项对应。
- **D 时间轴**：D1 统一 `useGlobalFrame(startSec)`；D2 时间常量集中在 `TL`；D3 缓动只允许 4 条命名曲线 + LINEAR（线性须显式标注）。
- **E 确定性**：E1 Canvas/图片/字体必须 `delayRender`/`continueRender`；E2 字体不打包必须做回退版式测试；E3 渲染参数写进交付（`--crf 16–20`、faststart，暗部色带看联系表）。
- **F 评分口径**：F1 先跑客观指标再看质感；F2 工具链问题单列「工具链分」；F3 交付分 <4 时其余分不能作为「规范通过」依据。

### E.3 v0.3 增补（A–G，ORIGAMI 后）

- **A 揭示式转场**：A1 先露主体再展开覆盖物（禁止盖满到结尾才开）；A2 覆盖物要有方向与折痕；A3 揭示中主体/主光应可见或半可见。
- **B 常驻主角**：B1 太阳/地平线/准星放 Sequence 外；B2 分镜加「跨镜头」列，换段只变状态。
- **C 分层质感**：C1 层叠结构至少深 2 阶 + 1 条墨线；C2 装饰服务叙事节点；C3 片尾四件套（标题/副标题/域名/署名）。
- **D validator**：D1 每题一份 brief pack（elements + 检测器）；D2 查「交付顺序」五件套；D3 过程日志的「动画原语选择」抽成词典。
- **E 原语词典**（6 条）：clip-path + 透视（折纸/揭页）；SVG stroke-dashoffset（墨线/轮廓）；种子随机 + 闭式运动（纸屑/粒子/飞鸟）；混合模式 + 旋转缩放（印章/套印）；radial/conic-gradient（日出/光扫）；径向渐隐（舞台聚焦）。
- **F 三个一**：每轮 1 规范 + 1 validator 规则 + 1 设计规则。
- **G 当前差距**：v2 已过 validator 但人工对比仍落后 Claude（构图/节奏/细节）；下一版改「缝隙先露日、山峦墨线、印章纸屑时序、标题署名位置」；目标 v1.0 随机出题时差距 <20%。

### E.4 v0.3 追加（H–O，v3 验证后；工作区未提交）

- **H 揭示细则**：铰链放画外左右边缘（放折缝会变成从外向内）；rotateY 必须配 perspective；缝要够亮（亮纸线 + 暖漏光）；揭示 ≥1.5–2s 用 inOut。

## F. Validator 现状与用法

### F.1 位置与调用

权威副本：`09-技术验证-remotion/tools/validator/`（`validate.mjs` / `metrics.py` / `briefs/origami-sunrise.json`）。

~~~bash
# 只看文件（Claude 回复 txt 或源码目录）
node tools/validator/validate.mjs --submission src/origami-claude/原文.txt

# 加命题包（推荐）；有 --brief 才检查元素与交付顺序
node tools/validator/validate.mjs --submission src/origami \
  --brief tools/validator/briefs/origami-sunrise.json \
  --video out/origami-mine-v3.mp4 \
  --report out/validator-origami-v3-report.md

# 先渲染再检查（提交必须已注册 Composition）
node tools/validator/validate.mjs --submission src/origami --brief <brief.json> \
  --render --composition OrigamiMine
~~~

- 不写 `--brief` 时，若提交目录有 `brief.json` 自动用；否则退回 v0.2 通用关键词（仅参考，**不计入 pass**）。
- 退出码：0 PASS / 1 FAIL / 2 用法或 brief 读不到；报告写 `--report`，同名 `.json` 存原始结果。

### F.2 检查项（v0.3）

1. **结构**：tokens / parts / Main / ≥3 镜头文件 / 文件块无说明混入。
2. **规格**：分辨率 / 帧率 / 帧数（可被 `brief.expect` 覆盖）。
3. **确定性**：Math.random、Date.now、setTimeout、setInterval、CSS animation、transition 六禁。
4. **视觉约束**：颜色数量 + brief 白名单、字体族数量。
5. **命题元素**：`brief.elements` 逐项检测；`policy.requireAllElements` 为真时缺一即 FAIL。
6. **交付**：`brief.delivery.items` + `order`；无 brief 时退回 ASSUMPTION/分镜/自检/风险。
7. **画面**：平均亮度 ≥10、近黑帧 ≤5%、内容覆盖率（参考，不设门槛）、可选四色占比。

### F.3 brief.json 能力清单（v0.3 D1）

~~~json
{ "id": "...", "expect": {"width":1280,"height":720,"fps":50,"frames":600},
  "palette": {"max":4,"allowed":["#F4EBDD","#22201C","#C8452B","#D6A84B"]},
  "fonts": {"maxFamilies":2},
  "metrics": {"avgY":10,"darkPct":5},
  "policy": {"requireAllElements":true},
  "elements": [{"id":"...","label":"...","required":true,"match":"all|any","detectors":[...]}],
  "delivery": {"order":["storyboard","processLog","selfCheck","risks"],"items":[...]} }
~~~

| 检测器 | 参数 | 用途 |
|---|---|---|
| regex | pattern / flags / scope（all/code/tokens） | 关键词存在性 |
| file | pattern | 文件名匹配 |
| count | pattern / min / max | 次数（如「≥3 层山峦」） |
| span | pattern（两组捕获 = 起止秒）/ min / max / scope | 时长（错位 ≤0.3s、hold ≥0.8s） |
| before | a / b（各一捕获组）/ scope | 先后顺序（缝隙早于展开） |
| metric | name / op / value | 画面指标；无 `--video` 时跳过 |

可用指标：`avgY`、`darkPct`、`brightPct`、`minBrightPct`、`redPct`、`goldPct`、`inkPct`、`paperPct`。颜色占比让「日出必须有红色主体」这类要求**可度量**，不再只是关键词。现有唯一命题包：`origami-sunrise.json`，15 个元素检测器 + 5 项交付 + 顺序。

## I. 红线与工作方式

1. **不重置用户配置**：`~/.dsh/dsh-startup.json`、`~/.dsh/startup-templates/`、`~/.dsh/chat-wallpaper.json`（及其目录）只能读、只能备份，不能覆盖用户内容。任何实验都不许写这些路径。
2. **不 force push、不删分支、不删 Release**；push 后用 `git ls-remote` 核对远端（网络常 reset，「看起来成功」不算）。
3. **先渲染再交付**：没有 mp4 + 1fps 联系表 + 3 张关键帧 + 目视结论，不算完成；Claude 给不出渲染物时由我们代渲染，且不得把「它说渲染过」当成证据。
4. **不告诉 Claude 内部评测背景**：提示词里不出现「测试/验收/规范验证/v1.0/打分」，只给命题、硬性要求与 5 步交付顺序；目的是学它的拆分与取舍，不是应试，也不涉及训练/蒸馏。
5. **只增补不推翻**：v0.1 是宪法，新经验写成 v0.x 增补；合并进正文要等 v1.0。
6. **规则进文件，不进对话**：每个决定落到 `STATUS.md` 或增补；不确定就写 **待确认** 或 ASSUMPTION，不编。
7. **工具链问题与规范问题分开记分**（v0.2 F2）；否则规范会被工具缺陷带偏。
8. **备份优先**：整仓快照进 `08-备份`；实验目录 `09-技术验证-remotion` 不在 01-源码 的 git 仓库内（实测无 `.git`），产物只存在磁盘上——要留档需手动备份。
9. **人机协作**：给用户的验收清单一律是「看什么、期望什么、不对反馈什么」，不贴代码。

## 附：术语

- **许愿式**：用户只描述想要的动画，AI 按规范产出代码模板，工具链负责校验/渲染/安装。
- **Bible / 圣经**：就是《代码模板规范》，目标 v1.0。
- **brief pack**：一题一份的命题包（规格 + 调色板 + 元素检测器 + 交付清单），让 validator 不写死 HUD 关键词。
- **三个一**：每轮学习必须产出 1 条规范 + 1 条 validator 规则 + 1 条设计规则。
- **联系表**：1fps 拼图，用于目视全片节奏。
