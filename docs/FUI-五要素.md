# FUI 五要素 · 学习笔记

> 用途：**自己学习/对照用**，不是插件里的主题预设。
> 来源：用户 2026-10-19 观看 FUI 设计讲解后的口述转译，整理成可对照的检查表。

## 0. 什么是 FUI

FUI = **Fictional User Interface**（虚构界面）。科幻电影、游戏里那些"看着像电脑界面、实际上没人真会用"的界面。
它不是现实 UI 的还原，而是**对现实的类型化夸张**——所以判断标准不是"真实吗"，而是"像不像那个世界的系统"。

## 1. 闪 / 故障艺术

- 现实故障 ≠ FUI 故障：真电脑死机是卡住、延迟、报错框
- FUI 的闪，更像**早期显像管电视**的扫描不稳、信号丢失
- 表现手段：逐行抖动、色偏、整帧瞬移、亮度呼吸、扫描线
- 作用：让界面"有生命、有年代感"，同时掩盖低精度观感

**检查项**：我们的故障效果是否像"老电视信号"，而不是"程序崩溃"？

## 2. 颜色单一 / 受限色盘

- 一部 FUI 通常只有：**一个主色 + 一个副色 + 中性白**
- 现实系统里红黄蓝绿四色齐全；FUI 一定**缺一两个**
- 目的不是省钱，是**让观众快速识别角色/阵营**（钢铁侠红橙、绿巨人绿）
- 本质是复古：早期显示器颜色数有限

**我们的色盘（鲸鱼蓝）**

| 角色 | 色值 |
| --- | --- |
| 主色 | `#1E48BA` 深蓝 |
| 副色 | `#72A2EA` 浅蓝 |
| 中性 | `#F4F8FF` 白 |
| 底 | `#04070D` 近黑 |

**检查项**：任意截一张图，能立刻说出主色吗？画面里有第三、第四个抢眼的颜色吗？

## 3. 暗底亮字

- 即"夜间模式"：背景近黑，文字与符号高亮
- 虽然可读性差，但在电影院里**眼睛会被亮的东西吸引**
- 游戏 UI 同理，黑底白字是默认

**检查项**：背景够黑吗？有没有大面积的中间灰抢走注意力？

## 4. 缓慢且有节奏地载入

- 现实交互：打开瞬间出现，或有转圈等待，但**不会慢悠悠位移/展开**
- 现实中动画一般 ≤200ms
- FUI 反过来：**打开/关闭要数秒甚至数十秒的过场**，元素**依次**出现/消失
- 关键不是"慢"，而是**有节奏的慢**（错落、有先后、有停顿）

**检查项**：我们的时间线里，元素是"一起淡入"还是"依次登场"？有没有留白停顿？

## 5. 装饰信息

- 满屏小字、数字、"十字符号"来来回回
- **没有任何含义**，纯粹为了让画面显得复杂
- 现实 UI 的信息都是"必要且要读清楚"；FUI 反过来——看着复杂，实际是装饰

**检查项**：我们的伪代码雨/读数/坐标够不够密？有没有"看起来在处理什么"的感觉？

---

## 落地对照表（我们现有的东西）

| 要素 | 现有能力 | 还缺 |
| --- | --- | --- |
| 闪 / 故障 | `glitch` 效果、扫描线、CRT 闪烁 | 更"电视信号"的逐行撕裂 |
| 单一色盘 | 主题 `theme.accent` 等 | 全模板统一到鲸鱼蓝三色 |
| 暗底亮字 | 模板默认黑底 | 部分模板中间灰偏多 |
| 节奏载入 | 时间线关键帧、逐字出现 | 元素"依次登场"的编排约定 |
| 装饰信息 | 伪代码雨、HUD 四角、读数文字 | 代码雨密度不够（现在"不像雨"）、缺滚动读数 |

## 一句话

> FUI 不是"把界面做酷"，而是**用有限的颜色、夸张的故障、刻意的慢、和无意义的细节**，让人相信"这是另一个世界的系统"。
