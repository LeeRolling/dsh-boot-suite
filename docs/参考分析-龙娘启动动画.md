# 参考分析：龙娘启动动画（codex-startup-animation）

来源：<https://github.com/mytjxs/codex-startup-animation>（v1.0.0 发布包，40 MB）
分析日期：2026-10-18　分析人：DeepSeek（应 LeeRolling 要求）

## 一、它到底是什么效果

**不是 CSS/SVG 做的 3D 模型，也不是 Live2D**，作者在 README 里写得很清楚：
"这不是实际可旋转的 3D 模型、骨骼绑定或 Live2D 工程"。

真实做法是「**2D 边缘描线 + 材质渐显**」：

1. 对闭眼人物图做**边缘检测**（`StrokeTrace.ExtractEdges`）
2. 沿边缘像素**描线**成折线（`Trace` / `Follow`），太短的丢掉（< 38 单位）
3. **断开处连接**：端点靠近且切线一致的线接起来（`Join`）
4. **平滑与分类**：按空间距离重采样 → 直线走直线、弧线走三次贝塞尔、明确拐角保留（`SmoothCurve`）
5. **排时序**：每条线单独给 `Start` 和 `Duration`，发丝主线先画、短线错开补齐（`Initialize`）
6. **按弧长生长**：每帧裁出"已画"部分 + 渐淡尾迹 + 移动亮头 + 高斯外发光 + 亮芯（`Lines/Tail/Light/Hot`）
7. **材质渐显**：线网之上叠加人物位图，透明度渐入，线网同步退去
8. 最后睁眼用 121 个眼睑过渡帧（预生成图集，OpenCV 光流制作）

**成品是预渲染的 MP4**（2560×1440 / 60fps / 8s / 480 帧），启动器只用 WPF 的 MediaElement 播它。
也就是说：它把渲染成本提前到制作期，播放时零成本。

## 二、和我们已有的东西对比

我们的鲸鱼标识 `assembleLogo` 已经在做同一件事的极简版：
`getTotalLength()` + `strokeDasharray/strokeDashoffset` 一笔画成。

差别只在规模：它几百条线、每条独立时序、带光迹与辉光；我们一条路径、一次性画完。

所以**原理我们已经有**，缺的是「多路径 + 时序 + 图片资产」这三块。

## 三、在我们这边做的可行性（实测）

在他们的闭眼角色图（1024×1536）上跑了一版纯 Python 可行性脚本（512 宽）：

| 指标 | 512 宽 | 折算 2K |
|---|---|---|
| 边缘像素 | 60,909 | — |
| 描出的线数 | 186 | ~186 |
| 总点数 | 58,571 | ~200k |
| SVG 路径数据（未简化） | 744 KB | ~2.6 MB |

**结论：直接照搬会太重**（2.6 MB 路径 + 数百条线，开机时从 HDD 读、还要逐帧改属性）。
必须做三件事才能进引擎：

1. **简化折线**（Douglas-Peucker，容差 1px）→ 通常能砍 60–80% 点数
2. **在 512 坐标系里提取，靠 viewBox 放大** → 坐标精度要求低，体积再降
3. **路径编码压紧**（相对命令 + 1 位小数）→ 每点约 6–8 字节

按经验估：简化 + 压缩后约 **80–150 KB**，线数控制在 120–200 条，浏览器侧可行。

## 四、要加什么（引擎 v2 的第一块）

| 层 | 内容 | 估时 |
|---|---|---|
| 离线工具 | `tools/trace-image.py`：边缘检测 → 描线 → 简化 → 平滑 → 输出 `paths.json` | 1 天 |
| 运行时 | SVG 层：多路径逐条 `stroke-dashoffset` 动画 + 光迹尾 + 移动亮头 + 辉光滤镜 | 1–1.5 天 |
| 模板字段 | `effects: { draw: { asset, start, stagger, dur, glow } }` + 图片资产 | 0.5 天 |
| 性能验证 | 200 条线在 1080p/60fps 下的帧时间、首帧加载时间 | 0.5 天 |

合计约 **3 天**，可拆成两步：先离线工具（能出图看效果），再进运行时。

## 五、两个提醒

1. **素材版权**：那个包里的角色图是作者/委托方的，我们只学技术、不复用素材。
   用户若要这个效果，需要提供自己有权的图（或我们自己生成一张）。
2. **别走"预渲染 MP4"那条路**：他们的产物是 40 MB 包 + 8 秒定死；
   我们的插件要能装任意模板、要能换文案，必须实时渲染。
