## ② 代码级规律（20 条）

分组：A 时间与确定性（R1–R7）｜B 画布与布局（R8–R11）｜C 绘制与性能（R12–R16）｜D 文字（R17）｜E 交付与自包含（R18–R19）｜F 组织与验收（R20）。

### R1 · 时间入口必须是「四件套」，不是「一个 draw(t)」

**做法**：任何可出片的实现都同时提供 ①`?t=` URL 参数（单帧静画）②`window.__seek(t)`（程序跳帧）③`window.__duration`（总长）④`window.__ready`（首帧已画完的信号）。四者齐全，外部抓帧脚本才存在。

**证据**
- `X7H:834-838`：`window.__seek=function(t){ playing=false; tNow=((t%T)+T)%T; render(tNow); last=performance.now(); return tNow; };` → `__play` → `__duration=T` → `render(0)` → **最后才** `window.__ready=true`。
- `B6O:312`：只给了 `window.__draw=draw; window.__canvas=cv;` 两个钩子（少 `__duration/__ready`，抓帧脚本得自己猜长度）。
- `B6O:315-316`：`?t=` 命中就 `draw(parseFloat(q)); return;`——**早退，不启动 rAF**，保证抓帧时零并发。
- `B6D`：全文 grep 无任何 `window.__`（决定性反例），同一份提示词另一个模型就漏了。
- `X7D:57-63`：正是因为 `__seek(t)` 存在，`capture.mjs` 才能 `--fps 30 --dur 16` 逐帧抓、再 `ffmpeg -crf 20` 编码。

**引擎规则**：IR 编译产物**强制**注入 `__seek/__play/__duration/__ready`；`__ready` 必须在首帧 `render()` 之后置位；`__seek` 内部必须（a）停播放（b）时间归一化（c）渲染（d）重同步时钟基准。缺任一 → 编译期报错，不是警告。

### R2 · 时长编码：`frames = round(dur × fps)` 必须整除，时长取「整齐数」

**做法**：把总时长当帧数问题处理，而不是秒的问题。所有样本的总长都让「秒×fps」落在整数帧上，且秒数本身是可整除的整齐值。

**证据**
- `V3:32-34`：`exactly 10.000 s (300 frames)`，30 fps —— 唯一把帧数写进规格的一篇。
- `B3:28`：4 段 × `PER=4.8s` = 19.2s（在 30fps 下 576 帧，在 24fps 下 460.8 帧——**19.2 是给 30fps 选的**）。
- `B6P:21` 12s；`X7H:395` `var T = 16.0;`；`L36:14` 「Suits films of 30–60 s」。
- `V3:73-75` 终检项第一条就是 `exactly 10.00 s / resolution / loudness`。

**引擎规则**：IR 只接受 `{duration, fps}`，编译期算 `frames=round(duration*fps)` 并**回写** `duration=frames/fps`（消除 10.001 这类漂移）；循环素材额外约束 `duration % segment === 0`（`B3` 的 4×4.8、`X7H` 的 16s 循环点 15.10 后回到 0）。不满足就调整并记录 `durationAdjusted`。

### R3 · `seek` 语义必须显式声明 `wrap` 还是 `clamp`

**做法**：同一份提示词下，两个实现给出了**两种互不兼容**的 `?t=` 语义，而且都没写进提示词。

**证据**
- `B6O:174`：`t=((tIn%TOTAL)+TOTAL)%TOTAL` —— 取模循环（t=13 等价 t=1）。
- `X7H:834`：`tNow=((t%T)+T)%T` —— 同样取模（因为是 loop 素材）。
- `B6D:486`：`draw(clamp(staticT, 0, DURATION))` —— **钳制**（t=13 等价 t=12，画面停在最后一帧）。
- `B6P:15-17` 的原文只写了「对 12 取余」，没有约束 `?t=` 的越界行为。

**引擎规则**：IR 字段 `time.seekMode: "wrap" | "clamp"`，默认 `"wrap"`；出片抓帧器按此推导越界时间；两种模式在验收上不同（wrap 必须「末帧→首帧」可拼，clamp 必须末帧是终态）。

### R4 · 单一时钟 + dt 上限；绝对时钟和增量时钟各有硬伤

**做法**：渲染只依赖内部 `t`，外部时钟只做「推进」或「设定」，且对单帧 dt 设上限。

**证据**
- `B6D:501-507`：`const delta = clamp((now-last)/1000, 0, 0.05); if(!paused) elapsed += delta; draw(elapsed % DURATION);` —— 增量累加，**上限 0.05s**（切标签页回来不会瞬移一大段）。
- `X7H:821-827`：`tNow=(tNow+Math.min(dt,0.1))%T` —— 同样增量，上限 0.1s。
- `B6O:317-328`：`t = (now-start)/1000` —— 绝对时钟，**切标签页会跳**（它自己也没修）。
- 三者的共同点：`t` 是唯一的可渲染状态，`last/start` 只是辅助量。

**引擎规则**：IR 编译产物只暴露 `advance(dt)` 和 `setTime(t)` 两个写入口；`dt` 上限默认 0.05s（出片）/0.1s（屏上预览）；禁止在 `render(t)` 内读 `performance.now()`。

### R5 · 用 t 反查状态索引，不要用「update 累加」

**做法**：序列动画写成 `states[] = [{t0, ...}]`，每帧用 `findLast(t)` 得到当前段，再算段内进度。这是纯函数 `render(t)` 能成立的前提。

**证据**
- `A2:29`：`let i=0; while (i+1 < s.st.length && s.st[i+1][0] <= tm) i++;` —— 按时间戳推进索引（不累加计数）。
- `F2:23`：`const p = eOut((tm - t0) / .7)` —— 边动画进度由 `tm - t0` 直接算。
- `X7H:414`：`function kf(t, pts)` —— 关键帧表插值，同样是 `t` 的函数。
- `L36:56`：drafting order 也是一张有序表（中心线→轮廓→细节→排线→尺寸→气球→标签），按序取。
- 反例 `A1:20,26`：`const dt=clamp(t-(s.lt??t),0,.05); s.lt=t;` + `d.y+=d.v*dt` —— 官方参考实现里就有帧积分，见 ⑤。

**引擎规则**：IR 的每条轨道编译成 `stateAt(t)`，禁止「上一帧 + Δ」作为唯一实现；需要物理感时用闭式解或预计算表（`V3:79-81` `"Seeded randomness only; physics… precomputed or closed-form"`）。

### R6 · 确定性随机四律（比「禁 Math.random」多三条）

**做法**：
1. 固定种子 `mulberry32(SEED)`；
2. 取数发生在**初始化阶段**，一次取完；
3. **取数顺序即接口**——顺序变了画面就变，所以顺序要写注释、要冻结；
4. 逐个元素派生子种子，而不是共享一个全局序列。

**证据**
- `LIB:10`：`rng(seed)` = mulberry32（`a=(a+0x6D2B79F5)>>>0`，`Math.imul`）。
- `B3:23`：「`mulberry32(2026)` 只在启动生成一次」。
- `B6O:76`：注释原文「粒子参数（顺序固定，保证可复现）」，`B6O:77-93` 单循环里按固定字段顺序取 rand。
- `B6D:82`：`const rand = mulberry32(7)`（顶层一次）。
- `X7H:540-541`：`rnd(sh*3)`、`rnd(sh*7)`、`rnd(sh*13)` —— **每个碎片用自己的 id 派生种子**，所以碎片顺序无关。
- 反例：`G1:19,26,28,30` 与 `X7H:552,557` 用 `Math.random()`（见 ⑤）。

**引擎规则**：IR 必须带 `random.seed`；编译期 AST 扫描 `Math.random` 直接失败；参数生成标注 `phase: "init"`；对多实例元素提供 `rngFor(id)`（`seed ^ hash(id)`），使数组重排不改变外观。

### R7 · 缓动是固定小集合 + 时间窗调用 + 区间取值

**做法**：缓动只用一个封闭集合，且在提示词里写成「区间」而不是「一个数」。

**证据**
- `LIB:5-9`：`clamp` / `lerp` / `ss(a,b,x)`（smoothstep）/ `eOut = 1-(1-t)^3` / `eBack`（`c=1.70158`）——整个 26 篇就这 5 个。
- `LIB:9` 的 `1.70158` 与 `V3:56` 的 `cubic-bezier(0.34,1.56,0.64,1)` 是同一个 overshoot 感的两种写法（Web 用 bezier、Canvas 用 eBack）。
- 时间窗调用：`B3:48` `e=smoothstep(2.4,4.2,q)`（0–2.4 停住、4.2–4.8 落定）；`B6P:81` 首尾淡入 `1-smoothstep(0,0.35,t)` + `smoothstep(11.4,12,t)`；`B6D:46-49` 把 smoothstep 实现写进代码。
- 区间取值：`V3:62` 「hook in the first 0.5 s…never open on more than 0.3 s of empty or black」；`L36:48` `Hold ≥ max(1.8 s, speech + 0.6 s)`；`V3:57` 「stagger 2~4 帧」。

**引擎规则**：缓动枚举固定 5 种（linear/clamp、lerp、smoothstep、easeOutCubic、easeBack），自定义曲线必须能归约到 bezier 参数；所有时长字段接受 `[min, max]` 区间，编译期按 `fps` 量化到帧。

### R8 · 画布尺寸与 DPR 分流：主画布固定输出分辨率，DPR 只进离屏

**做法**：出片用主画布 = 输出分辨率（1920×1080）**整数 1:1**，缩放交给 CSS/transform；`dpr` 参数只出现在离屏画布工具函数里。

**证据**
- `B6O:14` `<canvas width="1920" height="1080">` + `B6O:8-10` 纯 CSS 保比例（**零 JS、零 resize 监听**）：`width:100vw;height:56.25vw;max-height:100vh;max-width:177.78vh`。
- `B6D:474-480`：JS `fit()`，`scale=min(innerW/W, innerH/H)` 后写 `canvas.style.width/height`。
- `X7H:813-817`：第三种，`stage.style.transform="translate(-50%,-50%) scale("+s+")"`（stage 固定 1600×900）。
- 三者**都没有用 devicePixelRatio**。
- 唯一带 dpr 的是工具函数：`LIB:17` `offscreen(w,h,dpr)`（尺寸乘 dpr + `setTransform(dpr,0,0,dpr,0,0)`，最小 1px）；`G1:17` 的签名第 6 参就是 dpr，但 `G1:18` 调用时传 `offscreen(256,256,1)`——**自己都不用 2**。

**引擎规则**：IR 分两个尺寸字段：`output {w,h}`（出片，必为偶数，默认 1920×1080）与 `view {scale:"css"|"js"|"transform", maxLetterbox:true}`；`dpr` 只允许出现在 `fx.offscreen.dpr`，默认 1。理由：成片是 1920×1080 视频，提高 dpr 只增成本不改交付物。

### R9 · 单位制二选一并写死：`min(w,h)` 相对单位 或 1920 绝对坐标

**做法**：所有尺寸要么是画布短边的比例，要么是 1920 基准下的像素数，**不混**。

**证据（相对单位派）**
- `G1:21` `m=Math.min(w,h)`，`glowDot(...,m*.4,...)`。
- `E3:18` 网格 `cs=Math.max(7,Math.round(Math.min(w,h)/26))`（同时 clamp 下限 7px）。
- `A1:19` 字号基准 `base=Math.min(w,h)/17`。
- `F2:18` `m=Math.min(w,h), fs=Math.max(10,m/20)`。
- `C2:31`（同库另一篇）`c.lineWidth = Math.max(1.4, Math.min(w,h)/220)`。

**证据（绝对坐标派）**
- `B6P:21` / `B6D:33-36`：`W=1920 H=1080 CX=960 CY=540`，投影写死 `sx=960+f·X/d`。
- `B6O:18-22` 常量表 + `FONT`。

**引擎规则**：IR `layout.units: "min-side" | "px"`；`min-side` 下所有数值 ∈ (0,1]（渲染时乘短边）；`px` 必须同时给 `base:[1920,1080]`；混用直接报错。`clamp` 下限（如字号 ≥7px、线宽 ≥1px）必须显式写在 IR 里，不靠渲染时临时 Math.max。

### R10 · 安全区与构图比例是硬数字（不是「注意留白」）

**做法**：把「主体多大、离边多远、字幕放哪」写成可断言的数值。

**证据**
- `L36:77`：`Keep the main figure at least 960/zoom from any sheet edge you will frame` —— 安全距离是**随 zoom 反比**的函数，不是定值。
- `L36:65-75` 镜头表：`Medium on a figure, subject ~80 % of height`；`2× close-up cut on a downbeat`；`Oblique depth factor 0 → 0.5`。
- `V3:66-68`：`~5% safe margins`；`B3:63` 字幕固定在 `(960,960)` 居中 —— 960/1080=88.9%，即**下 11% 是字幕带**。
- `L36:48`：字幕「per shot 放在空白天空，绝不固定底部」，`wrap ~880px`（1920 的 45.8%）。
- `X18:20`：`Composition: 2x2 grid + gutter/spine`（版式即网格+沟槽宽度）。

**引擎规则**：IR 必须有 `safe {inset: 0.05, subjectHeight: 0.8, subtitleZone: {y: 0.889, width: 0.458}}` 三件；渲染前用包围盒做一次断言，越界按 `fit | clamp | fail` 处理（默认 `fit`）。

### R11 · 版式 = 0–1 坐标表 + 单一投影函数（布局与渲染解耦）

**做法**：元素位置存归一化坐标 `[x,y]∈[0,1]²`，渲染时只经过**一个**投影函数换算到像素；版式改动只改表。

**证据**
- `F2:19`：`const Nd = { 我:[.5,.55], 爸爸:[.22,.3], 妈妈:[.78,.3], 奶奶:[.5,.12], 学校:[.2,.82], 工作:[.8,.82] }`。
- `F2:22`：`const R=m*.075, at=k=>[Nd[k][0]*w, Nd[k][1]*h]` —— 全篇只有这一个 `at()`。
- `F2:20`：边也走同一投影（端点从圆心沿 `atan2` 方向内缩 R）。
- `E3:22`：`ax=(x-.5)*w/h` —— 宽高比校正也发生在投影层。

**引擎规则**：IR 的 `layout.nodes: {id: [x,y]}` 一律归一化；渲染层提供唯一 `project([x,y]) → [px,py]`；任何元素不得直接写像素坐标（`px` 单位模式除外，且要标 `absolute:true` 以便审查）。

### R12 · ctx 状态卫生：每帧复位、save/restore 配平、改过的必须还

**做法**：`globalCompositeOperation`、`globalAlpha`、`setLineDash`、`shadowBlur` 这些「黏住」的状态，用完立刻在同函数内还原；每帧开头统一复位一遍。

**证据**
- `B6O:179-181`：每帧先 `setTransform` / `globalAlpha` / `composite` 复位再画。
- **composite 必复位**（5 处独立代码同一模式）：`B2:20`→`B2:28`、`C1:23`→`C1:28`、`D2:23`→`D2:25`、`D3:21`→`D3:23`、`G2:20`→`G2:22`、`G1:26`→`G1:27`。
- `F2:26,28`：虚线用完 `setLineDash([])`、`globalAlpha` 还原。
- `E2:20,24`：`c.save()` 包住 `shadowColor/shadowBlur/shadowOffsetY`（阴影会污染后续所有绘制）。
- `B6D` 全文 API 计数：`save()=4 / restore()=4`（配平）、`globalAlpha=11`。

**引擎规则**：编译产物生成统一 `beginFrame(c)`：`setTransform(1,0,0,1,0,0)` + `alpha=1` + `composite="source-over"` + `setLineDash([])` + `shadowBlur=0`；每个 `save()` 静态配对一个 `restore()`，不配对即编译失败。

### R13 · 线宽/虚线是「尺度或深度」的函数，永远不是常量

**做法**：线宽 = `k/zoom` 或 `k/depth`，并夹在上下限之间；近处粗、远处细，否则近景变香肠、远景消失。

**证据**
- `L36:29`：四档线宽 `3.2 / 2.0 / 1.25 / 0.9 sheet units`，且 `Screen width = sheet width × zoom^0.65`（**幂次 0.65**，不是线性）。
- `L36:30`：dash 间距随 zoom 同步缩放。
- `L36:108`（Pitfalls）：`Line weights not scaled with zoom → sausages in close-ups, vanishing wides.`
- `B6O:230-246`：圆环不用 `ctx.arc`，而是**手绘 96 段**，因为每段的屏幕线宽要按该点的 `d` 单独投影。
- 相对写法：`C2:31` `lineWidth = Math.max(1.4, Math.min(w,h)/220)`；固定写法：`B4:23` `lineWidth=.7`（1920 下的发丝线，也是刻意的常量）。
- 反面：`F2:27` 箭头长 `9px` 硬编码（1080p 之外就错）。

**引擎规则**：IR 的 `stroke.width` 只接受三种形式：`{abs: px}`（必须标 `base`）、`{rel: 画布短边比例}`、`{depth: k, min, max}`；虚线 `dash` 必须与 `width` 同源缩放；禁止在循环里写字面量宽度。

### R14 · 粒子预算按「N × pass」三档，并显式剔除退化几何

**做法**：粒子数不是一个数，是「粒子数 × 每颗 pass 数」的乘积；性能不够时降 pass，不降粒子。

**证据**
- `B3:61-62`：每颗画 3 次（t / t−0.045 / t−0.09，α=1/.5/.25），**且都是重算位置，不存历史**。
- `B3:73` 自检第三条原文：5000×3 若卡，**只给 glow 粒子画光晕**（减 pass）。
- `B6P:69`：拖尾两端 `d<30` 或两端 `|d差|>500` 就跳过整条线（隧道绕回的退化几何）。
- `B6O:225`：`lineTo(...+0.01)` —— 给零长线段一个极小的偏移，否则某些后端不画点。
- `B6O:212`：同样的 `A.d<30||B.d<30|||A.d-B.d|>500 → continue`。
- `B6D` 绘制面极小：`arc=2`、`fillText=3`、`strokeText=0`、`createLinearGradient=0`、`clip=0`（全片只靠 line/fillText）。

**引擎规则**：IR `fx.particles {count, passes, cull: {near, farDelta}, glowOnlyBelowFps}`；编译期算 `budget = count*passes` 并与 `level`（low/mid/high）挂钩；退化几何（零长、反向、越界）在几何层剔除，不进绘制层。

### R15 · 纹理只生成一次，靠 pattern / 独立图层 + blend 复用

**做法**：噪点、纸纹、网点这类后处理纹理，一次生成（≤512² 或独立 canvas 图层），用 `createPattern`/`mix-blend-mode` 平铺，绝不每帧写全屏 `ImageData`。

**证据**
- `G1:18` 生成 `256×256` 噪点贴图 → `G1:26` `c.createPattern(s.nz,'repeat')` + `globalAlpha=.22` + `'overlay'` + 每帧只随机 `translate(-ox,-oy)` 平铺一次。
- `X7H:388`：纹理是**独立图层** `<canvas id="grain" width="1600" height="900">`，`X7H:548-563` 一次性铺 1.44M 像素噪点（`v=198+Math.random()*57`，B 分量 ×0.97 偏暖）+ 14 个随机污渍；主画布不碰像素。
- `X7H:42,61,110,116`：网点直接用 CSS `background-size:16px 16px` + `mix-blend-mode:screen|multiply` + `opacity`，**零 canvas 成本**。
- `X7D:44-48`：Ben-Day 网点=两层偏移 radial-gradient + multiply，一层 mask 让点向地平线变大，phase 慢漂 → 「呼吸」。
- `E2:29`：纸纹 `globalAlpha=.5` + `'multiply'` + `drawImage(s.paper,...)`（预生成纸纹 canvas）。
- `LIB:18-24` `paperTex(w,h,dpr,base,seed)`：点数 = `w*h/40`，划痕 = `w*h/900` —— **纹理密度是面积的函数**，不是常量。

**引擎规则**：IR `fx.texture {kind, size≤512, density, seed, blend, layer:"main"|"overlay"}`；`generate:"once"`；一旦出现「每帧 createImageData 全屏」即编译失败。叠加顺序固定：底 → 主体 → 纹理 → 暗角 → 字幕。

### R16 · 叠加靠 composite 分工，不靠改色

**做法**：发光用 `lighter`，压暗/染色用 `multiply`，颗粒/纸纹用 `overlay`，画完立刻回 `source-over`。同一个「变亮」意图，用 composite 表达比手算颜色更稳。

**证据**：`B2:20`（`lighter`，萤火）、`D2:23`（`lighter`，窗光）、`D3:21`（`lighter`，雪与火星）、`C1:23`（`multiply`，水墨）、`G1:26`（`overlay`，颗粒）、`E2:29`（`multiply`，纸纹）、`B3:59`（`lighter`，粒子发光）；每一种都在下一次绘制前复位。

**引擎规则**：IR `blend: "normal"|"add"|"multiply"|"screen"|"overlay"` 只允许出现在「层」上，不允许出现在单个图元上；层渲染完自动弹回 `normal`。

### R17 · 文字：字号=双约束取小、排版=measureText、闪烁=方波、描边=缺口

**做法**：
- 字号由「宽度能放几个字」和「高度能放几行」两个约束取小；
- 光标/下划线的位置由 `measureText` 实测宽度决定，不用估算；
- 光标闪烁 = `floor(t*f)%2` 的方波（不是 setInterval）；
- 描边：canvas 里没有一处实现，SVG/DOM 里才是常态。

**证据**
- `A2:32`：`const fs = Math.min(w/10.5, h/7)` —— **10.5 字宽 / 7 行高**两个约束。
- `A2:33-34`：`c.fillText(str, x0, y0)` 后 `cx = x0 + c.measureText(str).width + fs*0.12`（0.12 = 光标间距系数）；`A2:36` 光标宽 `Math.max(2, fs*0.07)`、高 `fs*1.1`。
- `A2:35`：`on = since < .45 || Math.floor(tm*1.8)%2 === 0` —— 前 0.45s 常亮，之后 1.8Hz 方波。
- 字体常量：`LIB:2-3` `SANS = '"Noto Sans SC","PingFang SC",sans-serif'`、`MONO = '"IBM Plex Mono",ui-monospace,monospace'`（三回退 + 通用族）。
- 字体串会被模型逐字照抄：`B3:39` 的 `bold 340px "Noto Serif SC","Songti SC","SimSun",serif` 原样出现在 `B6D:124,438,451`。
- 描边证据只在矢量侧：`X7H:257` `.ct-main{fill:var(--paper); stroke:var(--ink); stroke-width:...}`；`X7H:432` `<g stroke="#f2e7d0" stroke-width="11" stroke-linejoin="round">`（先画粗描边垫底）；`X7H:191` `text-shadow:4px 5px 0`（**0 模糊硬阴影**）；`X18:20` 要求 `Typography: black with white/cream outline halo + drop shadow`。
- **26 篇参考实现里 `strokeText` 出现 0 次**（grep 实测），而 `X18` 的文字规范明确要求描边 → 这是素材自身的缺口。
- 缺字形降级：`B6O:112` `if (pts.length===0) pts.push([0,0])` —— 字体缺失时标题粒子塌成一点，见 ⑤。

**引擎规则**：IR `text {font:[family..., generic]（≥2 项且末项通用族）, size:{byWidth:字符数, byHeight:行数}, measure:"measureText", outline:{width: clamp(size*0.04,1,8), color, lineJoin:"round"}, shadow:{blur:0, offset:[4,5]}}`；`strokeText` 与 `fillText` 必须成对且同坐标；缺字形走 `fallback:"abort"|"box"`，默认 `abort`（出片模式）。

### R18 · 单文件自包含：数据内联、字体系统栈、禁 fetch/CDN

**做法**：一个 HTML 双击就能跑。数据用 `<script type="application/json">` 内嵌（不是 fetch，file:// 下会被 CORS 拦），字体只用系统栈，不引 CDN、不引库。

**证据**
- `PICK:153`：479KB 的 `<script id="data" type="application/json">{...}</script>` 全量内嵌；`PICK:156` `JSON.parse(document.getElementById('data').textContent)` —— 没有任何 `fetch`。
- `PICK:161-162`：`try{ ... localStorage ... }catch(e){}` —— 隐私模式/配额失败不影响主流程。
- `X7D:3-5`：`one self-contained HTML file: no libraries, no external fonts, no network requests`。
- `X7H:24-26`：三套系统字体栈兜住风格（`--display: Impact, "Haettenschweiler", "Arial Narrow", "Arial Black", sans-serif`）。
- `B6O:8-10` 缩放纯 CSS，无外部依赖；`B6D` 全文无外链。
- 反面：`LIB` 被 24 篇以「同一文件夹的 `_公共函数.js`」方式引用 —— 单文件交付时**必须把工具库内联**，否则复制即坏。

**引擎规则**：编译产物 = 单个 `.html`；数据走 `type="application/json"`；字体白名单=系统栈（≥3 回退）；网络访问白名单=空；`localStorage`/`clipboard` 全部 try/catch；工具函数内联进同一 `<script>`。

### R19 · 音频：默认静音，必须显式要；cue sheet 是音画唯一真相

**做法**：不写就没声音（这是工具的默认行为，不是缺陷）；要音频就必须给「音量/响度/峰值/事件表」四件套，且事件表与画面共用。

**证据**
- `RM:38`：原文「记得说要不要配乐和音效。不说的话，它多半做出来是没声音的」。
- `V3:33`：`H.264 MP4 with stereo AAC audio (48 kHz), −14 LUFS integrated, true peak ≤ −1 dBTP` —— **交付级数字**。
- `V3:48`：`~120 BPM; pop/boing/whoosh on each entry, synced to the frame`（每个入场一声音，按帧对齐）。
- `V3:64`：`Keep one cue sheet (beats and hit times) that both the picture and the sound read from` —— 音画共读一张表。
- `L36:86`：混音规则（音乐在语音下压到 ~0.36×、foley 减半、whoosh 低通、−14 LUFS）。
- `L36:55,57`：draw-on 的笔尖声按弧长触发；机构的 click 按 beat 归位。
- `X7D:21-38`：16s 素材的时间轴表精确到 0.01s（0.00/2.05/2.95/…/15.10），这就是 cue sheet 的形态。

**引擎规则**：IR `audio {enabled:false（默认）, targetLufs:-14, truePeak:-1, events:[{t, kind, gain}], silenceAllowed:true}`；未启用时产物必须显式声明 `silent:true` 并在报告里写一行，禁止「忘了」；事件时间必须与画面 beat 同源（同一个 `beatGrid`）。

### R20 · 组织与自检：五层命名 + 可执行断言

**做法 A（分层）**：按「职责」而不是「文件大小」分层，时间轴单独一层，字幕独立 buffer。

**证据**
- `L36:110-112`：`demo/paper.js`（WebGL2 compositor，负责合成/纸/颗粒）、`demo/draw.js`（drafting engine：相机、斜投影、draw-on、实体、排线、尺寸、气球、文字）、`demo/sheet.js`（版式壳：边栏/标题块/注释/雨/印章）、`demo/film.js`（timeline on a beat grid：机位、表演、字幕、声音事件）、新机器另开 `demo/machine.js`。
- `L36:32`：三个 buffer（ink / fx / subtitle overlay last）—— **字幕必须在最上层独立 buffer**，因为它不能遮线、不能出格。
- `X7H` 的对应物是 DOM 分层：`#cam`（相机层）/ `#flipStack`（翻页层）/ `#grain`（纹理层）/ `#vignette`（暗角层）/ `#banner`（字幕层），`X7H:45,71,389`。
- `B3/B6/B1` 等单文件实现把这些压成一个 `draw()`，代价是超过 300 行后改不动。

**做法 B（自检）**：自检不是「写完看一眼」，而是三条可执行的断言 + 一张打分表；断言能机器跑，打分只能人跑。

**证据**
- `B3:69-73`：`## 写完后自己过一遍（不要输出）` 三条 —— ①同一个 t 刷新两次画面是否一模一样 ②`t=1.8` 是不是心、`t=3.3` 是不是在炸开 ③5000×3 会不会卡（卡就只给 glow 画光晕）。
- `V3:66-67`：`render stills at 6–10 key times and actually look at them`（静帧要真看，不是只生成）。
- `V3:73-75`：终检是**数值断言**——`exactly 10.00 s`、分辨率、响度、无黑帧、无 fallback font/tofu、无出框、细线不闪、无渐变 banding。
- `V3:98-100`：7 轴 1–10 打分，`6 = template-level, 8 = high-end agency, 9 = award shortlist`，`fix whatever scores lowest first`。
- `X7D:68`：`--times 3.9,5.9,8.1 --format png` —— 静帧点写进命令行，可重跑。
- `RM:43`：「提示词写得越细，不同模型做出来越接近」——自检的第一性目标是**收敛**，不是好看。

**引擎规则**：`selfCheck {stills:[6–10 个 t], sameTwice:true, framesAssert:true, score7:{…}}`；断言失败要能定位到具体时间点（输出 PNG + 该帧的 IR 状态快照）；7 轴打分写进交付报告，最低分项必须附带一条修改计划。

## ④ 给 anim-ir 的 10 条硬约束（字段 / 默认值 / 失败兜底）

| # | 字段 | 默认值 | 硬约束 | 失败兜底 |
|---|---|---|---|---|
| C1 | `output {w,h}` + `view.scale` + `fx.offscreen.dpr` | `1920×1080`, `scale:"css"`, `dpr:1` | w/h 必须偶数且 ≥320；`dpr` 只允许出现在离屏；主画布不得乘 dpr | 奇数→向下取偶并警告；`scale:"js"` 时自动生成 resize 监听；`dpr>1` 且 `output` 已定 → 忽略并记 `ignoredDpr` |

| C3 | `time.seekMode` | `"wrap"` | 只能 `wrap|clamp`；`seek(t)` 必须停播→归一→渲染→重同步时钟 | 非法值→`wrap` 并警告；`clamp` 模式末帧必须等于终态，否则校验失败 |
| C4 | `time.maxDt` | `0.05`（出片）/`0.1`（预览） | `render(t)` 内禁读 `performance.now()`；只暴露 `advance(dt)`/`setTime(t)` | 检测到时钟读取→编译失败；`dt` 超限→截断 |
| C5 | `random {seed, phase, perId}` | `seed:7`, `phase:"init"`, `perId:true` | 禁 `Math.random`（AST 扫描）；参数生成必须在 init 阶段；多实例用 `rngFor(id)` | 命中 `Math.random`→编译失败；顺序不稳定→用 `perId` 自动改写 |
| C6 | `layout {units, base, safe}` | `"min-side"`, `[1920,1080]`, `{inset:0.05, subject:0.8, subtitleY:0.889}` | `min-side` 的数值 ∈(0,1]；`px` 必须带 `base`；混用报错；包围盒必须落在 safe 内 | 越界→按 `fit` 缩放到 safe（`mode:"fail"` 时直接报错）；负值/零→拒绝 |
| C7 | `motion.tracks[].{t0,dur,stagger}` | `stagger: 2/fps`（≈66ms） | 全部秒；`t0+dur ≤ duration`；stagger 量化到帧；同刻只允许一个主动体 | 越界→裁剪到 `duration` 并警告；stagger <1 帧→取 1 帧 |
| C8 | `text {font, size, outline, shadow, fallback}` | `["Noto Sans SC","PingFang SC",sans-serif]`, `outline.width=clamp(size*0.04,1,8)`, `shadow.blur=0` | font ≥2 项且末项为通用族；`strokeText` 与 `fillText` 成对同坐标；`lineJoin="round"` | 字体缺失→`fallback:"abort"`（出片）或 `"box"`（预览），禁静默塌陷 |
| C9 | `fx {particles.count, passes, texture.size, cull}` | `count:2000`, `passes:1`, `size:256`, `cull:{near:30, farDelta:500}` | `count*passes ≤ budget(level)`；纹理 `generate:"once"` 且 `size≤512`；禁每帧全屏 `ImageData` | 超预算→先降 `passes` 再降 `count`（并写 `downgraded`）；纹理每帧生成→编译失败 |
| C10 | `deliver {hooks, selfCheck, audio}` | `hooks:["seek","play","duration","ready"]`, `selfCheck.stills:8`, `audio.enabled:false` | 四个钩子必须注入且 `__ready` 在首帧后；`stills` 取 6–10 个关键时间点；音频启用时必须给 `targetLufs:-14, truePeak:-1` | 缺钩子→编译失败；静帧渲染失败→保留其余并报 `partialStills`；未启用音频→报告写 `silent:true` |

补充三条「元约束」（不占上面 10 条，但必须写进校验器）：

1. **同 t 两次渲染必须逐像素一致**（`B3:71` 第一条自检）——不一致直接判失败，不给容差。
2. **每个 `save()` 必须有配对 `restore()`**，每个 composite/alpha/lineDash 改动必须在同函数内还原。
3. **交付物必须能被外部脚本驱动**：`capture --fps N --dur D` 只依赖 `__seek/__duration`，不读源码。

## ⑤ 不建议照抄的坑

按「会直接毁掉确定性或交付」排序。

1. **官方参考实现自己就在做帧积分**：`A1:20,26` `dt=clamp(t-(s.lt??t),0,.05); s.lt=t; d.y+=d.v*dt`。这违反它自己在 `B3:23` 立的规矩（同 t 必同帧）。学它的初始化与淘汰策略，**不要学它的运动学**。
2. **一次性纹理也用了 `Math.random`**：`G1:19,26,28,30`（抖动/颗粒偏移/暗闪/划痕）与 `X7H:552,557`（噪点、污渍）。页面只跑一次所以「看起来稳定」，**每次刷新/每次录制结果都不同**。要复现必须换 `rng(seed)`。
3. **字体缺失直接塌成一点**：`B6O:112` `if (pts.length===0) pts.push([0,0])`。这是个静默失败：画面没报错，标题变成一粒沙。必须走 `fallback:"abort"` 或至少画占位框。
4. **`?t=` 语义两头不一**：`B6O:174` 取模 vs `B6D:486` 钳制，同一份提示词。抓帧脚本按 wrap 写就会在末段取错帧，且不会报错。
5. **DeepSeek 版一个钩子都没留**：`B6D` 全文无 `window.__`，`B6O:312` 至少给了 `__draw/__canvas`。纯函数 ≠ 可驱动，两者要分开要求。
6. **绝对时钟切标签页会跳**：`B6O:317-328` 用 `(now-start)/1000`，标签页后台节流后回来会瞬移；`B6D:502`/`X7H:823` 都加了 `dt` 上限，说明这是已知问题。
7. **硬编码小尺寸**：`F2:27` 箭头长 `9px`、`F2:18` 字号下限 `Math.max(10,...)`（4K 下小到看不清）；`B4:23` 的 `lineWidth=.7` 只在 1× 输出成立。凡是没有 `base` 的像素值都是雷。
8. **`measureText` 用得极少**：全库只有 `A2:34` 一处（光标定位）。换行/居中靠硬编码（`L36:48` `wrap ~880px`），一换字号就崩。
9. **479KB 全量 JSON 内嵌**：`PICK:153` 把 341 条连同中英双 prompt 塞进一个 `<script>`。file:// 友好，但首屏解析明显；真要做索引应拆成「列表轻量 + 详情按需」（`PICK:277` 已经用 `<details>` 做了惰性构建，可以扩到数据层）。
10. **单文件里塞 CSS 字符串**：`X7H:467` 在 JS 里拼 `style="...font-family:var(--letter)..."`。可读性与可维护性都差；`X7` 的价值在「一句话→完整作品」的产出，不在工程结构。
11. **字幕没有独立层**：`L36:104` 明确列为失败模式（`Subtitles on the ink buffer vanish off-sheet and can't occlude lines`）——字幕画在 ink buffer 会出格、且会遮住线条。三个示例里只有 `X7H` 用了独立层（`#banner`）。照抄 `B6` 那种「最后 fillRect 一坨文字」的写法会踩这个坑。
12. **音频默认就是没有**：`RM:38`。所有没写音频的提示词，产物都是静音的；不要以为「做出来应该有环境音」。
13. **`prefers-reduced-motion` 全库 0 处**（416 行 `PICK` 只有 `prefers-color-scheme`，`PICK:13`；两个示例 HTML 也没有）。这是共同盲区，别照抄。
14. **`L36` 的 7 条「媒介失败模式」可直接当反模式清单用**（`L36:102-108`）：主体贴边、向上爆炸撞 header、字幕画进 ink 层、被自身阴影压暗、逐瓣着色像葡萄、小 payoff 撑不住、线宽不随 zoom。这些是**该风格特有**的，但每一条都能翻译成通用校验项。
15. **别把「9 分」当口号**：`V3:98-100` 的 7 轴打分要求「fix whatever scores lowest first」，是流程约束；只抄一句「aim for 9」不会让产物变好。

## 附：一页速查

- 出片三件套：`__seek(t)` / `__duration` / `__ready`（`X7H:834-838`）
- 时间：`frames=dur*fps` 整除，`dt≤0.05`，只暴露 `advance/setTime`
